Volcano#

Kubernetes 原生批处理调度系统，提供 Gang Scheduling、队列管理、优先级抢占和公平调度。

与 Kueue 的一句话差异：Volcano 在调度层做 Gang 判断（Pod 已创建，scheduler 整组评估）；Kueue 在准入层做 Gang 判断（资源不够零 Pod）。

版本#

组件 版本
Volcano v1.14.2
Helm chart 1.14.2

部署#

helmwave up --build

验证 Pod Running（应有 admission / controller / scheduler 各 3 副本，共 9 个）：

kubectl get pods -n volcano-system

⚠️ 与 Kueue 共存（必读）#

如果集群同时部署了 Kueue，Volcano 调度会被 Kueue Pod webhook 破坏：Kueue 的 mutating webhook 拦截所有非 kube-system namespace 的 Pod 创建，若 Pod 未带 kueue.x-k8s.io/queue-name label，会被注入 suspended=true 并覆盖 schedulerName。

解决方案：在 Kueue values.yaml 的 integrations.frameworks 中不要包含 pod 和 deployment，让 Kueue webhook 只处理明确标记的 Job 类资源。

使用#

1. Queue#

Volcano 安装时自动创建 root 和 default Queue，默认无资源上限，开箱即用。

# Volcano Queue 的 short name 是 q
# ⚠️ 不要用 kubectl get queue（会解析到 Kueue 的 LocalQueue）
kubectl get q
# 或用全名
kubectl get queues.scheduling.volcano.sh

仅在以下场景才需要 kubectl apply -f queue-setup.yaml：

  • 给 default Queue 设资源配额上限
  • 创建多租户子 Queue

2. PriorityClass#

kubectl apply -f priority-setup.yaml

提供 high-priority (10000) 和 low-priority (1000) 两个 K8s 原生 PriorityClass。

Volcano 用 Kubernetes 原生 PriorityClass，不是 Kueue 的 WorkloadPriorityClass。

3. TrainJob 接入 Volcano#

kubectl apply -f tests-phase1-runtime-volcano.yaml

TrainJob 提交模板（必须先建 PodGroup，再提交 TrainJob）：

---
# 1) PodGroup：手动创建，name 与下方 group-name annotation 一致
apiVersion: scheduling.volcano.sh/v1beta1
kind: PodGroup
metadata:
  name: my-training
  namespace: default
spec:
  minMember: 2          # = TrainJob.trainer.numNodes
  queue: default

---
# 2) TrainJob：runtimeRef 指向 volcano runtime，runtimePatches 注入 group-name annotation
apiVersion: trainer.kubeflow.org/v1alpha1
kind: TrainJob
metadata:
  name: my-training
  namespace: default
spec:
  suspend: false
  runtimeRef:
    name: torch-distributed-volcano
  trainer:
    numNodes: 2
    resourcesPerNode:
      requests: { nvidia.com/gpu: "1" }
      limits:   { nvidia.com/gpu: "1" }
  runtimePatches:
    - manager: scheduling.volcano.sh/volcano
      trainingRuntimeSpec:
        template:
          spec:
            replicatedJobs:
              - name: node
                template:
                  spec:
                    template:
                      metadata:
                        annotations:
                          scheduling.k8s.io/group-name: my-training

完整可运行示例见 tests-phase1-step1.yaml。原理见附录。

测试：分步排队验证（大 Gang 不阻塞小 Gang）#

前置：已 apply tests-phase1-runtime-volcano.yaml 和 priority-setup.yaml。

kubectl apply -f tests-phase1-step1.yaml  # 2 GPU  → PodGroup Running
# 等 step1 Pod Running 后：
kubectl apply -f tests-phase1-step2.yaml  # 24 GPU → PodGroup Pending（占满）
# 等 step2 PodGroup Pending 后：
kubectl apply -f tests-phase1-step3.yaml  # 2 GPU  → PodGroup Running（不被阻塞）

观察：

kubectl get trainjob -A
kubectl get podgroups.scheduling.volcano.sh -A
kubectl get pod -A | grep step

故障排查#

症状 检查命令 常见原因
PodGroup 一直 Pending kubectl describe podgroup <name> 看 Events 1. 集群剩余 GPU < minMember
2. minMember 与 TrainJob numNodes 不一致
Pod schedulerName 不是 volcano kubectl get pod <name> -o yaml | grep schedulerName Kueue Pod webhook 覆盖了 schedulerName（见部署 → Kueue 共存）
Pod 没关联到 PodGroup kubectl get pod <name> -o yaml | grep group-name runtimePatches 没注入 scheduling.k8s.io/group-name annotation
TrainJob 起不来但 PodGroup 不存在 kubectl get podgroup -n <ns> 忘了先创建 PodGroup 再提交 TrainJob（TrainJob 不走 VCJob webhook，PodGroup 不会自动建）

附录#

核心组件#

  • scheduler — 调度器，支持 gang / priority / drf / binpack / proportion 等插件
  • controller-manager — 资源控制器（Job / PodGroup / Queue 状态管理）
  • admission — webhook（VCJob 创建时注入 schedulerName 等默认字段）

为什么 TrainJob 必须手动创建 PodGroup#

  • VCJob admission webhook 会自动创建 PodGroup，但 TrainJob 不走此 webhook
  • Volcano PodGroup controller 会跳过已带 scheduling.k8s.io/group-name annotation 的 Pod（认为 PodGroup 已由 VCJob webhook 建好）
  • 所以必须先创建 PodGroup，再提交 TrainJob

Gang Scheduling 行为#

PodGroup 创建 → TrainJob 提交 → Pod 创建（schedulerName=volcano）
→ Volcano scheduler 评估 PodGroup
→ minMember 未凑齐 → 整组 Pending 等待
→ minMember 凑齐   → 整组 Permit → 全部 Running
  • 与 Kueue 不同：Volcano 资源不足时仍创建 Pod 并保持 Pending，存在调度开销
  • 与 scheduler-plugins Coscheduling 不同：Coscheduling 用 Pod label (scheduling.x-k8s.io/pod-group) 识别 Gang，Volcano 用 Pod annotation (scheduling.k8s.io/group-name) + PodGroup CRD

与 Kueue 共存的其他差异点#

维度 情况 说明
CRD short name queue 被 Kueue LocalQueue 占用 用 q 或全名查 Volcano Queue
PodGroup CRD 两个 PodGroup CRD 并存 scheduling.x-k8s.io vs scheduling.volcano.sh，API group 不同无冲突
Pod webhook 🔴 关键冲突 见部署 → Kueue 共存
