GPU Operator#

GPU Operator 用于支持配置 GPU 设备的 Kubernetes 集群, 主要包含安装 GPU 驱动，Container Runtime Nvidia, K8S Device Plugin 等

注意事项#

  • 不支持 ubuntu 20.04 版本

部署#

  • 部署 nfd 用于提供硬件特性检测服务, 并将其作为 Label 附加到节点上
  • 安装 GPU 驱动
    • [推荐] 在宿主机上安装 GPU 驱动, 版本参考 values.yml 中的 driver.version 配置
      • 下载 gpu driver
      • 执行 bash NVIDIA-Linux-x86_64-xxx.xx.xx.run 安装驱动
# 如果有之前残留旧版本驱动, 则进行卸载

# 通过 apt 安装的卸载方式
apt-get remove --purge '^nvidia-.*'

# 通过 run 安装的卸载方式
./NVIDIA-Linux-x86_64-*.run --uninstall
- [可选] 如果配备 NVLink 设备 (H100/H200/B200/B300) 还需要安装 `nv-fabricmanager` 服务, 参见 [Nvidia Fabric Manager User Guide](https://docs.nvidia.com/datacenter/tesla/fabric-manager-user-guide/index.html#bare-metal-mode)

apt install nvidia-fabricmanager-<driver-branch>
systemctl enable --now nvidia-fabricmanager

# B200/B300 额外安装 open 版本驱动和 nvlink5 包
apt-get install nvidia-open-<driver-branch>
apt-get install nvlink5-<driver-branch>

nvidia-smi -q -i 0 | grep -i -A 2 Fabric
    Fabric
      State                   : Completed
      Status                  : Success
  • [备选] 如果计划使用 GPU Operator 部署 GPU 驱动, 则修改
    • 修改 values.yml 中的 driver.enabled: true
    • 部署自定义配置 kubectl apply -k driver
    • 如果环境配置 Infiniband/RoCE 设备，且 GPU 是企业级卡（例如 A100, H100 和 B200 等） 则设置 values.yml 中的 driver.rdma.enabled: true 选项, 如果 IB/RoCE 驱动使用宿主机管理则设置 driver.rdma.useHostMofed: true
    • 设置 host 上 nvidia-smi 命令可执行
cat << 'EOF' > nvidia-smi.sh
alias nvidia-smi="chroot /run/nvidia/driver nvidia-smi"
EOF

pdcp -w ^all nvidia-smi.sh /etc/profile.d/
source /etc/profile.d/nvidia-smi.sh

  • 自定义 dcgm-exporter 配置和抓取指标到 vm 中

    修改 values.yml 中的 dcgmExporter.enabled: true

kubectl apply -k dcgm

在 Grafana 中添加 Nvidia DCGM Dashboard (Import 时使用 ID: 21362) 部署 vm 组件后执行：

kubectl apply -f dcgm/vm.yaml
  • 部署 helm chart
helmwave up --build

  • 测试

    运行一个 Cuda 示例用于检查基础环境是否准备好

kubectl apply -f tests.yaml
kubectl logs -f cuda-vectoradd
kubectl delete -f tests.yaml
  • 卸载
helmwave down

kubectl delete -k dcgm
kubectl delete -k driver

常见问题排错#

  • nvidia-cuda-validator-xxx pod init 启动失败
## 查看 init container 日志
$ kubectl logs -f nvidia-cuda-validator-bft5k -c cuda-validation
Failed to allocate device vector A (error code system not yet initialized)!
[Vector addition of 50000 elements]

## 上面错误通常是 nvidia-fabricmanager 启动失败
# 如果是宿主机部署的驱动，则需要检查宿主机上 nvidia-fabricmanager 是否启动成功
$ systemctl status nvidia-fabricmanager.service
# 如果是 pod 部署的驱动，则进入 driver pod 查看服务是否运行
$ kubectl exec -it nvidia-driver-daemonset-7s527 -- bash
> ps auxf |grep fabric
# 如果不存在，尝试手动启动
> nv-fabricmanager -c /usr/share/nvidia/nvswitch/fabricmanager.cfg
## 最后查看到 nvidia-fabricmanager 启动报错如下
request to query NVSwitch device information from NVSwitch driver failed with error:WARNING Nothing to do [NV_WARN_NOTHING_TO_DO]

## 上面错误通常可能是 nvswitch 设备没有被识别到
# 如果下面目录为空则表明，设备没有被识别到, 需要检查硬件
$ ls -l ll /proc/driver/nvidia-nvswitch/devices/ 

## 通常可以执行下面命令检查 nvidia-fabricmanager 是否正常, 下面状态是正常的
nvidia-smi -q -i 0 | grep -i -A 2 Fabric
  Fabric
    State                   : Completed
    Status                  : Success
