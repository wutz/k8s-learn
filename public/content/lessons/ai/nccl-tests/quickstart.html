NCCL Tests 快速指南#

测试分布式 GPU 集群的 NCCL 通信带宽。两件必做事：

# 任务 目标 all_reduce_perf 参数
1 单次测试 正确性验证 + 性能曲线 -b 8 -e 8G -f 2 -g 1
2 压力测试 持续满载打带宽，验证长稳 -b 8G -e 8G -i 0 -g 1

先做任务一，通过后再做任务二。

配置选择#

文件 GPU 网络 NCCL_IB_HCA NCCL_SOCKET_IFNAME -e
nccl-tests-5090.yaml RTX 5090 hostnet mlx5 bond0 8G
nccl-tests-5090-macvlan.yaml RTX 5090 macvlan mlx5 eth0 8G
nccl-tests-b200.yaml B200 hostnet mlx5 bond1 16G
nccl-tests-b300.yaml B300 hostnet roce_vf_rail bond1 64G
nccl-tests-a100-ib.yaml A100 macvlan ^=mlx5_4 eth0 8G

网络模式说明：

  • hostnet：无需额外组件，单节点不可并行多任务（端口冲突）
  • macvlan：需 Spiderpool + IPPool，Pod 独立 IP，可并行多任务
  • RoCE 网络用 hostnet 时必须设 hostNetwork: true

任务一：单次测试#

完成标准#

  • 日志输出 # Out of bounds values : 0 OK
  • 日志输出 # Wrong values : 0 OK
  • 峰值 busbw（最大 size 对应行）≥ 理论峰值 90%

步骤#

  1. 提交测试（以 5090 为例）
kubectl apply -f nccl-tests-5090.yaml
  1. 查看日志（完整日志含 NCCL 初始化）
kubectl logs -l trainer.kubeflow.org/replicated-job-name=launcher -f --tail=-1
  1. 判定：对照完成标准检查日志末尾。

任务二：压力测试#

完成标准#

  • 日志持续输出 8G 数据行的 busbw，无 NCCL error
  • busbw ≥ 理论峰值 90%
  • 持续运行达到预期时长后手动停止

步骤#

  1. 修改 YAML 中的 all_reduce_perf 参数

将 all_reduce_perf 命令行改为压测参数（以 5090 为例）：

sed 's|all_reduce_perf -b 8 -e 8G -f 2 -g 1|all_reduce_perf -b 8G -e 8G -i 0 -g 1|' \
    nccl-tests-5090.yaml > nccl-tests-5090-stress.yaml

# 预览确认
diff nccl-tests-5090.yaml nccl-tests-5090-stress.yaml

不同机型原始 -e 值不同（8G/16G/64G），替换时匹配 YAML 中的实际命令行。以下提供通用替换：

# 通用：匹配含 all_reduce_perf 的整行替换
sed '/all_reduce_perf/s|-b 8 -e .*-f 2 -g 1|-b 8G -e 8G -i 0 -g 1|' \
    nccl-tests-5090.yaml > nccl-tests-5090-stress.yaml
  1. 提交并查看日志
kubectl apply -f nccl-tests-5090-stress.yaml
kubectl logs -l trainer.kubeflow.org/replicated-job-name=launcher -f --tail=-1
  1. 停止压测（达到预期时长后）
kubectl delete -f nccl-tests-5090-stress.yaml

日志解读#

all_reduce_perf 输出关键字段：

#       size       time   algbw   error  busbw
#        (B)      (us)  (GB/s)     (%)  (GB/s)
            8     xx.xx     xx.x       0     xx       ← 最小 size，测延迟
           16
           32
           ...
   8589934592     xx.xx     xx.x       0   100.5      ← 最大 size，看这一行 busbw

# Out of bounds values : 0 OK                    ← 必须为 0 OK
# Avg bus bandwidth    : xx.xx
# Wrong values : 0 OK                            ← 必须为 0 OK
  • busbw（最后列 GB/s）：校正后总线带宽，直接对比硬件峰值
  • 理论峰值因机型而异，见 config-reference.md

压测日志#

压测命令 -b 8G -e 8G -i 0 固定 8G 持续运行，日志会重复输出 8G 数据行，每行含 20 次迭代均值。持续观察 busbw 是否稳定，关注是否有突降或 NCCL error。

性能基准#

评级 busbw / 理论峰值
优秀 ≥ 90%
可接受 80–90%
异常 < 80%

busbw 校正因子（all_reduce）：2(n-1)/n，n 为 GPU 总数。
