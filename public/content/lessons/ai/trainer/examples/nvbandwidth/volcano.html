NVBandwidth (Volcano)#

用途：测量 GPU 内存带宽和延迟（PCIe / NVLink / Host-Device），多租户优先级抢占场景使用。

快速运行#

# 提交测试
kubectl apply -f nvbandwidth.yaml

# 查看每个节点的测试结果
kubectl get pods --no-headers -o custom-columns=POD:.metadata.name,NODE:.spec.nodeName | grep nvbandwidth | while read -r POD NODE; do
  echo "########## Node: ${NODE} (Pod: ${POD}) ##########"
  kubectl logs "${POD}"
  echo "=================================================================="
done

# 清理
kubectl delete -f nvbandwidth.yaml

修改 yaml 中 mlPolicy.numNodes 和 PodGroup 的 minMember、minResources.nvidia.com/gpu 时需同步调整。

前置要求#

提交前验证：

# 1. Volcano 三组件 Running
kubectl get pods -n volcano-system

# 2. default Queue 存在且 Open
kubectl get queues.scheduling.volcano.sh default
# 期望：State=Open

# 3. 节点 GPU 已注册（任选一个节点验证）
kubectl get node <node-name> -o jsonpath='{.status.allocatable.nvidia\.com/gpu}'
# 期望：8（或更多）

预期输出#

每个 Pod 日志显示该节点的带宽测试矩阵：

nvbandwidth Version: ...
Running host_to_device_memcpy_ce
SUM host_to_device_memcpy_ce  xxx.xx GB/s

SUM 行接近 PCIe/NVLink 理论带宽即正常。

观察状态#

# PodGroup 是否凑齐 minMember
kubectl get podgroups.scheduling.volcano.sh nvbandwidth
# Phase: Pending → Running 表示 2 节点 Pod 已凑齐

kubectl get trainjob nvbandwidth
kubectl get pod -l trainer.kubeflow.org/trainjob-name=nvbandwidth
