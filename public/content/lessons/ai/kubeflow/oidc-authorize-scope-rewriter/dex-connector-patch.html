Dex Connector 配置改动（启用 Adapter 时）#

把 my-kubeflow/dex/dex-config-patch.yaml 的 IAM connector 段改为：

connectors:
- type: oidc
  id: seres-iam
  name: 集团-AI训推平台
  config:
    # issuer 保持 IAM 真实值（token 校验时 iss claim 必须匹配）
    issuer: https://iam.seres.cn/idp/api/v3
    clientID: $IAM_CLIENT_ID
    clientSecret: $IAM_CLIENT_SECRET
    redirectURI: https://staii.seres.cn/dex/callback

    # ★★ 关键：用 Dex 原生的 discovery override 把 authorize 端点指向 adapter
    # adapter 会改写 scope 后 302 跳到 IAM 真实地址
    # token / jwks 端点不覆盖，Dex 仍直连 IAM
    providerDiscoveryOverrides:
      authURL: https://staii.seres.cn/oidc-authorize-scope-rewriter/authorize

    # scopes 保持现状即可；rewriter 会统一改成 scope=openid
    # - scopes: []        → Dex 可能生成 openid+profile+email
    # - scopes: [openid]  → Dex v2.45 可能生成 openid+openid
    # 两种都会被 rewriter 改为单一 openid
    scopes: []

    insecureSkipEmailVerified: true
    userIDKey: sub
    userNameKey: sub
    getUserInfo: false

部署后验证#

# 1. Dex 重载配置后日志确认 connector 加载成功
kubectl rollout restart -n auth deploy/dex
kubectl logs -n auth deploy/dex --tail=20 | grep -E "connector|seres-iam"

# 2. 看 Dex 实际生成的 302 Location（应指向 adapter）
# 浏览器开 DevTools Network 标签，访问 https://staii.seres.cn/，
# 点 "集团-AI训推平台" 登录按钮，看跳转链：
#   Dex /dex/auth/seres-iam → 302 → staii.seres.cn/oidc-authorize-scope-rewriter/authorize?...&scope=openid+profile+email
#   或 Dex v2.45 在 scopes: [openid] 时生成 scope=openid+openid
