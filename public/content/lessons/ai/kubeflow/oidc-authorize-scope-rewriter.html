OIDC Authorize Scope Rewriter#

拦截 Dex 发往赛力斯 IAM 的 OIDC authorize 请求，把 scope 重写为单一 openid，绕过 IAM 对额外 scope 的拒绝（Dex v2.45 OIDC connector 强制 prepend openid 导致 scope 重复，方案 D：authorize 重写 adapter）。

工作原理#

Dex（issuer 保持 IAM 真实值，仅覆盖 authorize 端点）
  ↓ providerDiscoveryOverrides.authURL 指向 adapter
浏览器 302 → /oidc-authorize-scope-rewriter/authorize?scope=openid+profile+email
  ↓ nginx 改写 scope=openid
302 → iam.seres.cn/idp/authCenter/authenticate?scope=openid
IAM 登录 → 回调 → Dex（不经 adapter）
Dex 直连 IAM token/jwks（不经 adapter）

只拦截 /authorize 一个端点，token/jwks/userinfo 走 IAM 真实地址。

前置依赖#

  • Istio + Kubeflow Istio Resources（VirtualService 绑定 kubeflow/kubeflow-gateway）
  • oauth2-proxy（AuthorizationPolicy 已排除 /oidc-authorize-scope-rewriter/*，wrapper 内置）
  • 外部 DNS staii.seres.cn → VIP 10.81.215.101

文件清单#

文件 作用
configmap.yaml nginx 配置，提取 4 参数（client_id/redirect_uri/response_type/state）+ scope=openid
deployment.yaml nginx:1.27-alpine，unprivileged（runAsUser 101），2 副本
service.yaml ClusterIP，port 80 → 8080
virtualservice.yaml Istio 路由 /oidc-authorize-scope-rewriter/* → adapter
namespace.yaml / kustomization.yaml namespace + 入口

dex-connector-patch.md 为初始配置参考文档，不参与部署。

部署#

kubectl apply -k ai/kubeflow/oidc-authorize-scope-rewriter/
kubectl get pod -n oidc-authorize-scope-rewriter       # 期望 2 Pod Running
kubectl rollout restart deployment/dex -n auth          # Dex 配置已内置 providerDiscoveryOverrides，重启生效
kubectl rollout status deployment/dex -n auth --timeout=60s

验证#

curl -sI "https://staii.seres.cn/oidc-authorize-scope-rewriter/authorize?client_id=JT_STAII&redirect_uri=https%3A%2F%2Fstaii.seres.cn%2Fdex%2Fcallback&response_type=code&scope=openid+profile+email&state=test" | grep -iE "^HTTP|^location"
# 期望：HTTP/2 302，Location 中 scope=openid

浏览器访问 https://staii.seres.cn/ → 点"集团-AI训推平台" → IAM 登录页 → 登录成功回到 Dashboard。

故障排查#

  • scope 仍含 profile/email：Dex 未重启或配置未生效 → kubectl exec -n auth deploy/dex -- cat /etc/dex/cfg/config.yaml | grep -A2 providerDiscoveryOverrides
  • 返回 404：VirtualService 未生效 → kubectl get virtualservice -n oidc-authorize-scope-rewriter
  • 返回 302 到 oauth2-proxy 登录页：AuthorizationPolicy 未排除路径 → kubectl get authorizationpolicy -n istio-system -o yaml | grep oidc-authorize-scope-rewriter
  • Pod CrashLoopBackOff：kubectl logs -n oidc-authorize-scope-rewriter <pod>

回滚#

kubectl delete -k ai/kubeflow/oidc-authorize-scope-rewriter/
# 删除 my-kubeflow/dex/dex-config-patch.yaml 中的 providerDiscoveryOverrides 段，重新 apply + 重启 Dex
kubectl apply -k my-kubeflow/dex
kubectl rollout restart deployment/dex -n auth
