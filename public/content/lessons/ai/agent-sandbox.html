Agent Sandbox#

Agent Sandbox 是 Kubernetes SIG Apps 下的开源项目，提供专为 AI Agent 运行时设计的声明式 API 和控制器。它解决传统 K8s 原语（Deployment/StatefulSet）无法满足 AI Agent 的有状态单例、间歇性活跃、安全隔离执行需求。

核心特性#

  • Sandbox CRD：有状态单例 Pod，提供稳定主机名和网络标识
  • SandboxTemplate：可复用的 Sandbox 配置模板
  • SandboxClaim：从模板请求 Sandbox 实例
  • SandboxWarmPool：预热 Sandbox 池，消除冷启动延迟（~0s 分配）
  • 强隔离：支持 gVisor（系统调用级）和 Kata Containers（VM 级）
  • 生命周期管理：暂停/恢复、缩容至零、持久存储

架构#

Agent 框架 (LangChain/OpenAI SDK)
    │
    ├─> SandboxClaim ──> SandboxWarmPool ──> Pre-warmed Sandbox Pod
    │
    └─> Sandbox Controller
            │
            ├─> gVisor (用户态内核拦截)
            └─> Kata Containers (轻量 VM 隔离)

前置依赖#

1. 安装隔离运行时#

方式 A：gVisor（推荐）#

# 安装 gVisor runsc
wget https://storage.googleapis.com/gvisor/releases/release/latest/x86_64/runsc
wget https://storage.googleapis.com/gvisor/releases/release/latest/x86_64/runsc.sha512
sha512sum -c runsc.sha512
chmod a+rx runsc
sudo mv runsc /usr/local/bin

# 配置 containerd
cat <<EOF | sudo tee /etc/containerd/config.toml
version = 2
[plugins."io.containerd.grpc.v1.cri".containerd.runtimes.runc]
  runtime_type = "io.containerd.runc.v2"
[plugins."io.containerd.grpc.v1.cri".containerd.runtimes.runsc]
  runtime_type = "io.containerd.runsc.v1"
EOF

sudo systemctl restart containerd

# 创建 RuntimeClass
kubectl apply -f - <<EOF
apiVersion: node.k8s.io/v1
kind: RuntimeClass
metadata:
  name: gvisor
handler: runsc
EOF

方式 B：Kata Containers#

# 安装 Kata Containers
sudo apt-get update
sudo apt-get install -y kata-runtime kata-containers-image

# 配置 containerd
sudo mkdir -p /etc/containerd
containerd config default | sudo tee /etc/containerd/config.toml
sudo sed -i 's/runtime_type = "io.containerd.runc.v2"/runtime_type = "io.containerd.kata.v2"/g' /etc/containerd/config.toml
sudo systemctl restart containerd

# 创建 RuntimeClass
kubectl apply -f - <<EOF
apiVersion: node.k8s.io/v1
kind: RuntimeClass
metadata:
  name: kata
handler: kata
EOF

部署#

本项目使用 Kustomize 管理配置，支持开发和生产环境的差异化部署。

Kustomize 部署（推荐）#

开发环境部署#

开发环境使用标准容器运行时（无需 gVisor/Kata），资源限制较宽松，便于本地测试：

# 部署到 default namespace
kubectl apply -k overlays/dev

# 验证部署
kubectl get sandbox
kubectl get sandboxtemplate

生产环境部署#

生产环境强制使用 gVisor 隔离，资源限制严格，部署到独立 namespace：

# 部署到 agent-sandbox namespace
kubectl apply -k overlays/prod

# 验证部署
kubectl -n agent-sandbox get sandbox
kubectl -n agent-sandbox get sandboxtemplate

传统脚本部署#

如果需要快速一键部署（不使用 Kustomize）：

./deploy.sh install

脚本会自动完成：

  1. 部署 Agent Sandbox Controller
  2. 创建 Python Sandbox Template
  3. 应用 RuntimeClass（gVisor/Kata）
  4. 部署示例 Sandbox

2. 验证部署#

# 检查 controller 状态
kubectl get deployment -n agent-sandbox-system agent-sandbox-controller-manager

# 检查 CRD
kubectl get crd | grep agents.x-k8s.io

3. 部署测试 Sandbox#

kubectl apply -f examples/basic-sandbox.yaml

# 检查 Sandbox 状态
kubectl get sandbox

# 查看 Sandbox Pod
kubectl get pods -l sandbox.agents.x-k8s.io/name=basic-sandbox

4. 测试隔离执行#

# 进入 Sandbox
kubectl exec -it <sandbox-pod-name> -- /bin/bash

# 测试隔离（gVisor 会拦截某些系统调用）
strace ls  # 可以看到 gVisor 的系统调用拦截

示例配置#

基础 Sandbox#

apiVersion: agents.x-k8s.io/v1alpha1
kind: Sandbox
metadata:
  name: basic-sandbox
spec:
  podTemplate:
    spec:
      runtimeClassName: gvisor  # 或 kata
      containers:
      - name: agent
        image: python:3.11-slim
        command: ["sleep", "infinity"]
        resources:
          requests:
            memory: "256Mi"
            cpu: "250m"
          limits:
            memory: "512Mi"
            cpu: "500m"

SandboxTemplate + SandboxClaim#

---
apiVersion: agents.x-k8s.io/v1alpha1
kind: SandboxTemplate
metadata:
  name: python-agent-template
spec:
  podTemplate:
    spec:
      runtimeClassName: gvisor
      containers:
      - name: agent
        image: python:3.11-slim
        command: ["sleep", "infinity"]
---
apiVersion: agents.x-k8s.io/v1alpha1
kind: SandboxClaim
metadata:
  name: my-python-agent
spec:
  templateRef:
    name: python-agent-template

SandboxWarmPool#

apiVersion: agents.x-k8s.io/v1alpha1
kind: SandboxWarmPool
metadata:
  name: python-warmpool
spec:
  replicas: 3  # 预热 3 个 Sandbox
  templateRef:
    name: python-agent-template

Sandbox Router#

Sandbox Router 是 Agent Sandbox 的网络代理组件，由 FastAPI 实现。它的作用是：

  • 统一入口：外部流量通过单一端点访问所有 Sandbox，无需逐个暴露 Pod IP
  • 路由转发：通过 HTTP Header X-Sandbox-ID 识别目标 Sandbox，将请求路由到对应 Pod IP
  • 服务发现：自动关联 SandboxClaim 与其分配的 Pod，维护路由表
  • 安全边界：配合 NetworkPolicy，Sandbox Pod 默认不可被外部直接访问，只能通过 Router 转发

架构#

外部 AI 框架 (LangChain, OpenAI SDK)
    │
    │  POST /execute
    │  Header: X-Sandbox-ID: my-agent-sandbox
    ▼
┌───────────────┐
│ Sandbox Router│  (FastAPI, K8s Service)
│  端口 8080    │
└───────┬───────┘
        │ 查找 X-Sandbox-ID → Pod IP 映射
        ▼
┌───────────────┐
│ Sandbox Pod   │  (隔离环境)
│  10.x.x.x    │
└───────────────┘

当前状态#

Sandbox Router 使用 GCP staging 镜像（us-central1-docker.pkg.dev/k8s-staging-images/...），在非 GCP 环境可能无法拉取。如果集群无法访问该镜像仓库，可以：

  1. 自行构建镜像（源码在上游仓库 clients/python/agentic-sandbox-client/sandbox-router/）
  2. 跳过部署 Router，直接通过 kubectl exec 或 port-forward 访问 Sandbox

常见问题#

1. Sandbox Pod 无法启动#

# 检查 RuntimeClass
kubectl get runtimeclass

# 检查节点是否支持 gVisor/Kata
kubectl describe node <node-name> | grep -i runtime

# 查看 Pod 事件
kubectl describe pod <sandbox-pod-name>

2. gVisor 系统调用被拦截#

gVisor 默认拦截某些危险的系统调用。如果需要更宽松的策略，可以在 /etc/containerd/config.toml 中配置 runsc 的 --platform 参数。

3. Kata Containers 性能问题#

Kata Containers 使用完整的 VM 隔离，启动时间比 gVisor 慢（150-300ms vs 亚秒级）。如果对冷启动敏感，建议使用 SandboxWarmPool 预热。
