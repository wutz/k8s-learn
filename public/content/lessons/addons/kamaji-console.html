部署 kamaji-console#

配置#

kubectl apply -f kamaji-console.yaml

部署#

helmwave up --build

  1. Replace Placeholders with Actual Values:

    • Edit kamaji-console.yaml (or create a separate Secret YAML for better security).
    • Provide real values for each field (e.g., a URL for NEXTAUTH_URL, a strong random string for JWT_SECRET, etc.).
    • Encode each value in base64 before inserting it into the YAML.

    Example commands to generate and encode values (on macOS/Linux):

    • For NEXTAUTH_URL (e.g., assuming "https://console.example.com/ui"):
echo -n 'http://192.168.3.103/ui' | base64

 Output: Something like `aHR0cHM6Ly9jb25zb2xlLmV4YW1wbGUuY29tL3Vp`
  • For JWT_SECRET (generate a secure random one):
openssl rand -base64 32 | tr -d '\n' | base64  # Double-encode if needed, but single base64 is fine

 Use the output directly.
  • For ADMIN_EMAIL (e.g., "admin@example.com"):
echo -n 'admin@example.com' | base64
  • For ADMIN_PASSWORD (use a strong password, e.g., generate with openssl rand -hex 16):
echo -n 'your-strong-password' | base64

Update the data section in the YAML to look like this (with your encoded values):

apiVersion: v1
kind: Secret
metadata:
  name: kamaji-console
  namespace: kamaji-system  # Adjust if needed
type: Opaque
data:
  NEXTAUTH_URL: <base64-encoded-url>  # e.g., aHR0cHM6Ly9jb25zb2xlLmV4YW1wbGUuY29tL3Vp
  JWT_SECRET: <base64-encoded-secret>
  ADMIN_EMAIL: <base64-encoded-email>
  ADMIN_PASSWORD: <base64-encoded-password>
  1. Apply the Updated YAML:
    • Run kubectl apply -f kamaji-console.yaml again.
    • If the Secret is already partially created, you might need to delete it first: kubectl delete secret kamaji-console -n kamaji-system (replace namespace if different).

Best Practices#

  • Don't Commit Secrets to Git: Avoid storing real encoded values in version control. Use tools like kubectl create secret generic kamaji-console --from-literal=NEXTAUTH_URL=https://console.example.com/ui --from-literal=JWT_SECRET=your-secret --dry-run=client -o yaml > secret.yaml to generate the Secret YAML dynamically, then apply it separately.
  • Use Helm for Installation: As mentioned before, the official way to install Kamaji Console is via Helm (helm install kamaji-console clastix/kamaji-console --namespace kamaji-system --create-namespace), which handles Secret creation and allows you to set values securely via --set flags (e.g., --set console.nextauthUrl=https://console.example.com/ui).
  • Verify After Apply: Check the Secret with kubectl get secret kamaji-console -n kamaji-system -o yaml (values will show as base64). Then, ensure the Deployment pods are running: kubectl get pods -n kamaji-system.
