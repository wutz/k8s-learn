K8S FAQ#

ETCD#

  • 问题
etcdserver: mvcc: database space exceeded

  • 原因

    • etcd 使用 MVCC（Multi-Version Concurrency Control）机制，每当 Kubernetes 对象（如 Pod、Secret、ConfigMap、Deployment 等）被创建、更新或删除时，都会产生一个新的 revision（版本历史）
    • 这些历史版本会积累，导致 etcd 的数据库文件（db 文件）不断增长
    • etcd 默认设置了一个后端配额 --quota-backend-bytes，默认值为 2GB（部分 Kubernetes 发行版如某些 RKE/Kublr 为 4GB），官方推荐最大不超过 8GB
    • 当数据库大小接近或超过这个配额时，etcd 会触发 NOSPACE alarm，进入维护模式，只允许读和删除操作，拒绝新写入。这会导致 Kubernetes API Server 无法正常工作，集群出现各种问题（如 Pod 无法调度、kubectl 命令失败等）

  • 短期解决方法, 压缩释放空间

    所有 etcd 节点都需要执行如下命令：

# 加载 etcd 环境变量
set -a && source /etc/etcd.env && set +a

# 查看 etcd 状态
etcdctl endpoint status --write-out=table --cluster
etcdctl alarm list

# 查看 etcd 版本    
revision=$(etcdctl endpoint status --write-out=json | jq '.[0].Status.header.revision')
# 压缩 etcd 数据
etcdctl compact $revision
# 碎片整理
etcdctl defrag
# 解除 alarm
etcdctl alarm disarm

  • 长期解决方法，增加 etcd 存储空间

    • 直接修改所有控制节点 etcd 配置并滚动重启 etcd 服务
vim /etc/etcd.env
ETCD_QUOTA_BACKEND_BYTES=8589934592

systemctl restart etcd
* 或者在部署 kubespray 时设置 etcd 存储空间

vim inventory/mycluster/group_vars/all/etcd.yml
etcd_quota_backend_bytes: 8589934592
  • 检查 quota 设置
set -a && source /etc/etcd.env && set +a

curl --cert $ETCDCTL_CERT --key $ETCDCTL_KEY --cacert $ETCDCTL_CACERT $ETCDCTL_ENDPOINTS/metrics |grep quota
> etcd_server_quota_backend_bytes 8.589934592e+09

Systemd Cgroup#

  • 问题：

    • 提交 GPU Pod 不设置 resources 申请 GPU 资源，并设置环境变量 NVIDIA_VISIBLE_DEVICES=all
kubectl apply -f - <<EOF
apiVersion: v1
kind: Pod
metadata:
    name: gpu-test
spec:
    restartPolicy: Never
    containers:
    - name: cuda
      image: nvidia/cuda:12.0.0-base-ubuntu22.04
      command: ["tail", "-f", "/dev/null"]
      env:
      - name: NVIDIA_VISIBLE_DEVICES
        value: "all"
* 在 host 上执行 `systemctl daemon-reload` 后，GPU Pod 内执行 `nvidia-smi` 报错如下：

nvidia-smi
Failed to initialize NVML: Unknown Error

  • 原因

    • 当容器运行时缺省使用 systemd cgroup 驱动时，执行 systemctl daemon-reload 会更新容器相关 cgroup
    • 这会导致容器 Pod 丢失 NVIDIA GPU 设备访问权限，使用 resources.limits.nvidia.com/gpu 已在 gpu-operator 22.9.2 通过注入设备软链接解决
    • 但是不设置 resources.limits.nvidia.com/gpu 时跳过对应逻辑处理

  • 方案

    • 短期解决方案，使用 cgroupfs 驱动

      • 修改容器运行时配置

        • 修改 containerd 配置文件 /etc/containerd/config.toml 设置 SystemdCgroup = false (共计 4 个)
        • 重启 containerd 服务 systemctl restart containerd

      • 如何使用 kubespray 部署或者扩容，则在 inventory/mycluster/group_vars/all/containerd.yml 中设置 containerd_use_systemd_cgroup: false

        • 这设置 runc.options 中的 SystemdCgroup: false
        • GPU Operator 提供的 nvidia-container-toolkit-daemonset 会从 runc.options 中读取 SystemdCgroup 设置来配置 nvidia runtime 使用 cgroupfs 驱动

      • 其它：从 k8s 1.31 开始 kubelet 开启自动探测 cgroup driver 后续版本废弃 kubelet 配置 cgroupDriver 参数, 即从 k8s 1.31 开始无需在 kubelet 配置 cgroupDriver 参数

    • 长期解决方案，使用 K8S DRA 实现跨 Pod 的 GPU 共享

  • 参考: Kubernetes containers using NVIDIA_VISIBLE_DEVICES lose device access after systemctl daemon-reload
