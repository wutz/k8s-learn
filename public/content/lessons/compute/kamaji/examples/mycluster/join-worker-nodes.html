添加工作节点到租户集群#

创建 Kamaji 租户控制平面后，需要添加工作节点来运行实际的工作负载。本文档介绍几种常见的添加工作节点的方法。

方式一：使用 kubeadm 手动加入#

1. 准备工作节点#

在工作节点上安装必要的组件：

# 安装容器运行时（以 containerd 为例）
apt-get update
apt-get install -y containerd

# 配置 containerd
mkdir -p /etc/containerd
containerd config default > /etc/containerd/config.toml
systemctl restart containerd
systemctl enable containerd

# 安装 kubeadm, kubelet, kubectl
apt-get update
apt-get install -y apt-transport-https ca-certificates curl
curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.29/deb/Release.key | \
  gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.29/deb/ /' | \
  tee /etc/apt/sources.list.d/kubernetes.list
apt-get update
apt-get install -y kubelet kubeadm kubectl
apt-mark hold kubelet kubeadm kubectl

# 启动 kubelet
systemctl enable --now kubelet

2. 获取 join token#

从管理集群获取 join token：

# 使用租户集群的 kubeconfig
export KUBECONFIG=tenant-kubeconfig.yaml

# 创建 join token
kubeadm token create --print-join-command

# 输出示例：
# kubeadm join 192.168.1.100:6443 --token abcdef.0123456789abcdef \
#   --discovery-token-ca-cert-hash sha256:1234567890abcdef...

3. 在工作节点上执行 join 命令#

# 在工作节点上执行（需要 root 权限）
kubeadm join 192.168.1.100:6443 \
  --token abcdef.0123456789abcdef \
  --discovery-token-ca-cert-hash sha256:1234567890abcdef...

4. 验证节点加入#

# 在管理集群上，使用租户集群的 kubeconfig
kubectl --kubeconfig=tenant-kubeconfig.yaml get nodes

# 应该看到新加入的节点
NAME          STATUS   ROLES    AGE   VERSION
worker-node   Ready    <none>   1m    v1.29.0

方式二：使用 Cluster API#

Kamaji 提供了 Cluster API Control Plane Provider，可以与 Cluster API 基础设施提供商集成，自动管理工作节点。

1. 安装 Cluster API 和 Kamaji Provider#

# 安装 clusterctl
curl -L https://github.com/kubernetes-sigs/cluster-api/releases/download/v1.6.0/clusterctl-linux-amd64 \
  -o clusterctl
chmod +x clusterctl
sudo mv clusterctl /usr/local/bin/

# 初始化 Cluster API（以 Docker 为例）
clusterctl init --infrastructure docker

# 安装 Kamaji Control Plane Provider
clusterctl init --control-plane kamaji

2. 创建 Cluster API 集群#

# 生成集群配置
clusterctl generate cluster tenant-cluster \
  --infrastructure docker \
  --control-plane kamaji \
  --kubernetes-version v1.29.0 \
  --worker-machine-count 3 > cluster.yaml

# 应用配置
kubectl apply -f cluster.yaml

# 等待集群就绪
kubectl wait --for=condition=Ready cluster/tenant-cluster --timeout=600s

3. 获取 kubeconfig#

# 获取租户集群 kubeconfig
clusterctl get kubeconfig tenant-cluster > tenant-kubeconfig.yaml

# 验证
kubectl --kubeconfig=tenant-kubeconfig.yaml get nodes

方式三：使用虚拟节点（Virtual Kubelet）#

对于无服务器或边缘场景，可以使用 Virtual Kubelet 创建虚拟节点。

1. 安装 Virtual Kubelet#

# 使用 Helm 安装（示例）
helm repo add virtual-kubelet https://virtual-kubelet.github.io/virtual-kubelet
helm install virtual-kubelet virtual-kubelet/virtual-kubelet \
  --set provider=mock \
  --kubeconfig=tenant-kubeconfig.yaml

2. 验证虚拟节点#

kubectl --kubeconfig=tenant-kubeconfig.yaml get nodes

# 应该看到虚拟节点
NAME                STATUS   ROLES   AGE   VERSION
virtual-kubelet     Ready    agent   1m    v1.29.0-vk

方式四：使用自动化脚本#

对于批量添加节点，可以创建自动化脚本。

join-node.sh 示例#

#!/bin/bash
set -e

# 配置参数
CONTROL_PLANE_ENDPOINT="${1:-192.168.1.100:6443}"
KUBECONFIG_PATH="${2:-tenant-kubeconfig.yaml}"

# 获取 join token
export KUBECONFIG="$KUBECONFIG_PATH"
JOIN_CMD=$(kubeadm token create --print-join-command)

# 在远程节点上执行 join
# 方式 1: 使用 SSH
# ssh user@worker-node "sudo $JOIN_CMD"

# 方式 2: 使用 Ansible
# ansible worker-nodes -m shell -a "$JOIN_CMD" --become

# 方式 3: 使用 cloud-init（云环境）
# 将 JOIN_CMD 添加到 cloud-init 脚本中

echo "Join command generated:"
echo "$JOIN_CMD"
echo ""
echo "Execute this command on worker nodes with root privileges."

网络配置注意事项#

1. 确保网络连通性#

工作节点需要能够访问：

  • 控制平面 API Server（默认 6443 端口）
  • Konnectivity Server（如果启用）
  • Pod 网络（根据 CNI 插件要求）

2. 配置防火墙规则#

# 工作节点需要开放的端口
# Kubelet API: 10250
# NodePort Services: 30000-32767
# CNI 插件端口（根据具体 CNI 而定）

# 示例：使用 ufw
ufw allow 10250/tcp
ufw allow 30000:32767/tcp

3. 安装 CNI 插件#

租户集群需要安装 CNI 插件来提供 Pod 网络：

# 示例：安装 Calico
kubectl --kubeconfig=tenant-kubeconfig.yaml apply -f \
  https://docs.projectcalico.org/manifests/calico.yaml

# 或安装 Cilium
helm repo add cilium https://helm.cilium.io/
helm install cilium cilium/cilium --version 1.14.5 \
  --namespace kube-system \
  --kubeconfig=tenant-kubeconfig.yaml

故障排查#

节点无法加入#

  1. 检查网络连通性
# 在工作节点上测试
telnet 192.168.1.100 6443
curl -k https://192.168.1.100:6443/healthz
  1. 检查证书
# 验证 CA 证书哈希
openssl x509 -pubkey -in /etc/kubernetes/pki/ca.crt | \
  openssl rsa -pubin -outform der 2>/dev/null | \
  openssl dgst -sha256 -hex | sed 's/^.* //'
  1. 查看 kubelet 日志
journalctl -u kubelet -f

节点状态为 NotReady#

  1. 检查 CNI 插件
kubectl --kubeconfig=tenant-kubeconfig.yaml get pods -n kube-system
  1. 检查节点条件
kubectl --kubeconfig=tenant-kubeconfig.yaml describe node <node-name>
  1. 检查容器运行时
systemctl status containerd
crictl info

最佳实践#

  1. 使用配置管理工具

    • 使用 Ansible、Terraform 等工具自动化节点配置
    • 维护节点配置的版本控制

  2. 节点标签和污点

# 为节点添加标签
kubectl --kubeconfig=tenant-kubeconfig.yaml label nodes <node-name> \
  workload-type=compute

# 添加污点（如果需要）
kubectl --kubeconfig=tenant-kubeconfig.yaml taint nodes <node-name> \
  dedicated=special-workload:NoSchedule

  1. 监控节点健康

    • 部署 Node Exporter 收集节点指标
    • 配置告警规则监控节点状态
    • 定期检查节点资源使用情况

  2. 安全加固

    • 最小化工作节点上的软件包
    • 配置 SELinux/AppArmor
    • 定期更新系统和 Kubernetes 组件
    • 使用 Pod Security Standards
