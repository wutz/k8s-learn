Istio#

Istio 扩展了 Kubernetes，以建立可编程、应用程序感知的网络。Istio 可与 Kubernetes 和传统工作负载配合使用，为复杂的部署带来标准、通用的流量管理、可观测和安全性。

Istio 同时实现 Ingress, Gateway API 和 Gateway API Inference Extension (GIE)。

在生产实践中可以按需选择使用, 例如在推理场景中只使用 Gateway API 和 GIE 即可。

Istio 对于 ServiceMesh 支持 2 种部署模式:

  • Sidecar：最早支持模式，在每个 Pod 中注入 Sidecar，优点支持 Istio 全部功能，缺点是消耗资源高以及延迟开销较大
  • Ambient: 1.22 开始生产可用，在每个节点启动支持 L4 实例 Ztunnel，使用 L7 增强功能按需启用，优点资源消耗小和延迟低

采用的 Ambient 模式, 为命名空间添加标签才会开启 L4 支持，L7 需要配置才会启用。

依赖#

  • spiderpool 与 Istio 的 Ambient 模式有兼容问题，所以采用 Sidecar 模式。
  • metallb

部署#

helmwave up --build

(可选) 配置 Istio 作为 Ingress Controller

(推荐) 配置 Gateway API 用于新服务
