Kube-OVN#

Kube-OVN 是一个基于 OVN 的 Kubernetes 网络插件，提供了丰富的网络功能，包括子网管理、网络策略、QoS、负载均衡等。

本文档说明如何在已有 Cilium 的集群中部署 Kube-OVN 作为 Secondary CNI。

前置条件#

  1. 集群已部署 Cilium：确保 Cilium 已正确部署并运行
  2. Cilium 配置：确保 Cilium 的 cni.exclusive 设置为 false（允许多 CNI 共存）
  3. 网络规划：确保 Kube-OVN 的 Pod CIDR 与 Cilium 的 Pod CIDR 不冲突

部署前准备#

1. 检查 Cilium 配置#

确保 Cilium 的 values.yml 中 cni.exclusive 设置为 false：

cni:
  exclusive: false

如果未设置，需要先更新 Cilium 配置：

cd network/cilium
# 编辑 values.yml，设置 cni.exclusive: false
helmwave up --build

2. 规划网络地址#

在部署前，需要规划以下网络地址，确保不与现有网络冲突：

  • Pod CIDR：Kube-OVN 的 Pod 地址段（默认：10.16.0.0/16）
  • Service CIDR：Kube-OVN 的 Service 地址段（默认：10.96.0.0/12）
  • Node Switch CIDR：节点交换机地址段（默认：100.64.0.0/16）

重要：确保这些地址段与 Cilium 和其他网络组件不冲突。

3. 修改配置#

编辑 values.yml 文件，根据实际情况修改以下配置：

  • ipv4.POD_CIDR：Pod 地址段
  • ipv4.POD_GATEWAY：Pod 网关地址
  • ipv4.SERVICE_CIDR：Service 地址段（如果与集群 Service CIDR 不同）
  • NETWORK_TYPE：网络类型（geneve 或 vlan）
  • TUNNEL_TYPE：隧道类型（geneve, vxlan 或 stt）

部署#

helmwave up --build

验证部署#

1. 检查 Pod 状态#

kubectl get pods -n kube-system | grep kube-ovn

所有 Pod 应该处于 Running 状态。

2. 检查 CNI 配置#

在每个节点上检查 CNI 配置文件：

# 在节点上执行
ls -la /etc/cni/net.d/

应该能看到：

  • Cilium 的 CNI 配置文件（优先级更高）
  • Kube-OVN 的 CNI 配置文件（10-kube-ovn.conflist，优先级为 10）

3. 测试 Pod 网络#

创建一个测试 Pod，使用 Kube-OVN 网络：

apiVersion: v1
kind: Pod
metadata:
  name: test-kube-ovn
  annotations:
    ovn.kubernetes.io/logical_switch: default
spec:
  containers:
  - name: test
    image: busybox
    command: ["sleep", "3600"]
kubectl apply -f test-pod.yaml
kubectl exec -it test-kube-ovn -- ping -c 3 8.8.8.8

使用 Kube-OVN 网络#

方式一：通过 Annotation 指定#

在 Pod 或 Namespace 上添加 annotation 来使用 Kube-OVN 网络：

apiVersion: v1
kind: Pod
metadata:
  name: my-pod
  annotations:
    ovn.kubernetes.io/logical_switch: default
spec:
  containers:
  - name: app
    image: nginx

方式二：通过 NetworkAttachmentDefinition（推荐）#

使用 Multus CNI 和 NetworkAttachmentDefinition 来管理多个网络接口：

apiVersion: k8s.cni.cncf.io/v1
kind: NetworkAttachmentDefinition
metadata:
  name: kube-ovn-net
  namespace: default
spec:
  config: |
    {
      "cniVersion": "0.3.1",
      "type": "kube-ovn",
      "server_socket": "/run/openvswitch/kube-ovn-daemon.sock",
      "ipam": {
        "type": "kube-ovn",
        "server_socket": "/run/openvswitch/kube-ovn-daemon.sock"
      }
    }

然后在 Pod 中使用：

apiVersion: v1
kind: Pod
metadata:
  name: my-pod
  annotations:
    k8s.v1.cni.cncf.io/networks: kube-ovn-net
spec:
  containers:
  - name: app
    image: nginx

与 Cilium 的配合#

网络策略#

  • Cilium：处理默认的网络策略（通过 CiliumNetworkPolicy 和 NetworkPolicy）
  • Kube-OVN：网络策略功能已禁用（ENABLE_NP: "false"），避免冲突

CNI 选择#

  • 默认：Pod 使用 Cilium 网络（优先级更高）
  • 指定使用 Kube-OVN：通过 annotation 或 NetworkAttachmentDefinition 指定

服务发现#

  • Cilium：处理默认的 Service 发现和负载均衡
  • Kube-OVN：可以创建自己的子网和逻辑交换机，提供额外的网络隔离

高级配置#

VLAN 模式#

如果需要使用 VLAN 模式（underlay 网络），修改 values.yml：

NETWORK_TYPE: "vlan"
TUNNEL_TYPE: "geneve"
vlan:
  VLAN_INTERFACE_NAME: "eth0"  # 物理网卡名称
  VLAN_ID: 100                  # VLAN ID

硬件卸载#

如果节点支持硬件卸载，可以启用：

HW_OFFLOAD: "true"

注意：启用硬件卸载需要：

  1. 节点支持硬件卸载功能
  2. 物理网卡绑定 IP 地址
  3. 禁用流量镜像

多网络栈#

Kube-OVN 支持 IPv4/IPv6 双栈，配置示例：

NET_STACK: "dual"
ipv4:
  POD_CIDR: "10.16.0.0/16"
  POD_GATEWAY: "10.16.0.1"
ipv6:
  POD_CIDR: "fd00:10:16::/112"
  POD_GATEWAY: "fd00:10:16::1"

故障排查#

1. Pod 无法获取 IP#

检查 Kube-OVN Controller 日志：

kubectl logs -n kube-system -l app=kube-ovn-controller

检查 CNI 配置：

# 在节点上执行
cat /etc/cni/net.d/10-kube-ovn.conflist

2. 网络不通#

检查 OVS 状态：

# 在节点上执行
ovs-vsctl show

检查路由：

# 在 Pod 中执行
ip route

3. CNI 冲突#

如果出现 CNI 冲突，检查：

  1. Cilium 的 cni.exclusive 是否为 false
  2. CNI 配置文件优先级是否正确
  3. 是否有多个 CNI 插件同时管理同一个 Pod

卸载#

helmwave down

注意：卸载前确保没有 Pod 正在使用 Kube-OVN 网络，否则可能导致 Pod 网络中断。
