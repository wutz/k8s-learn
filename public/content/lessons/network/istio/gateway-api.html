Gateway API 部署指南#

✅ 推荐方案: 这是 Kubernetes 官方推荐的下一代流量管理 API。

与 ../ingress/ 的关系:

  • ingress/ 使用 Kubernetes Ingress API（旧方案），保留用于过渡期参考
  • gateway-api/ 使用 Gateway API（新标准），推荐新服务使用
  • POC 验证结论：Gateway API 可完全替代 Ingress API

功能对比详见下文。

Gateway API 是 Kubernetes 官方的下一代流量管理 API，相比 Ingress API 提供更丰富的功能和更好的可扩展性。

前置条件#

  • Istio 已部署 (参考 ../README.md)
  • Gateway API CRDs 已安装 (Istio 部署时自动安装)

部署#

kubectl apply -k .

配置说明#

Gateway#

定义网关监听器，支持多域名、多协议：

apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: main-gateway
  namespace: istio-system
spec:
  gatewayClassName: istio
  listeners:
  - name: http
    hostname: "*.example.com"
    port: 80
    protocol: HTTP
    allowedRoutes:
      namespaces:
        from: Selector
        selector:
          matchLabels:
            gateway-access: main-gateway

HTTPRoute#

定义路由规则，支持路径匹配、Header 匹配、流量分割等：

apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: my-app
  namespace: my-namespace
spec:
  parentRefs:
  - name: main-gateway
    namespace: istio-system
  hostnames:
  - "my-app.example.com"
  rules:
  - backendRefs:
    - name: my-app
      port: 80

使用示例#

1. 为命名空间添加标签#

kubectl label namespace my-namespace gateway-access=main-gateway

2. 部署应用和 HTTPRoute#

参考 tests.yaml 中的示例。

3. 测试访问#

# 获取 Gateway 地址
GATEWAY_HOST=$(kubectl get gateway -n istio-system main-gateway -o jsonpath='{.status.addresses[0].value}')

# 测试访问
curl -HHost:my-app.example.com "http://$GATEWAY_HOST"

功能特性#

功能 支持状态 说明
HTTP 路由 ✅ Path/Header 匹配
URL 重写 ✅ 前缀/完整路径重写
TLS 终止 ✅ HTTPS 证书管理
多域名路由 ✅ 多域名隔离
Headers 操作 ✅ 添加/删除请求头、响应头
超时控制 ✅ 请求超时配置
流量分割 ✅ 加权流量路由
重试机制 ⚠️ 需要 EnvoyFilter 扩展

对比 Ingress API#

特性 Ingress Gateway API
路由规则 注解 + IngressRule HTTPRoute CRD
多命名空间 不支持 ✅ 支持
流量分割 不支持 ✅ 支持
Headers 操作 注解 ✅ 原生支持
可扩展性 差 ✅ 好
角色分离 差 ✅ 好
