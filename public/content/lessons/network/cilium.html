Cilium#

Cilium 是一个基于 eBPF 数据平面的网络、可观测性和安全解决方案。它提供了一个简单的扁平化三层网络，能够在原生路由或覆盖模式下跨越多个集群。它具有七层协议感知能力，并且可以使用基于身份的安全模型在三到七层上实施网络策略，该模型与网络寻址分离。

主要提供 CNI，Service 和 Networking Policies 等功能。

注意#

  • cilium 会占用 route table 200/202/2004/2005, 如果宿主机有网络也使用这些路由表, 则需要修改宿主机网络配置, 否则会导致网络异常

部署#

  • 修改 values.yml 中的 ipam.operator.clusterPoolIPv4PodCIDRList 配置: 需要询问用户
  • 修改 values.yml 中的 k8sServiceHost 配置: API Server 直连地址，使 Cilium init 容器绕过 ClusterIP 避免 iptables 竞态
    • Kubespray 部署的集群推荐 127.0.0.1（节点本地 nginx 代理，天然 HA）
    • 也可使用 VIP 地址（如 192.168.3.101），但依赖外部负载均衡
    • 不推荐 auto（从 kube-public/cluster-info 读取，kubeadm 写入的是单 master IP，无 HA）
  • 修改 values.yml 中的 k8sServicePort 配置: API Server 端口，默认 6443
  • 修改 values.yml 中的 bpf.enableTCX 配置为 false, 避免触发bug，参见 TCX BPF programs not cleaned up
helmwave up --build

高级配置#

  • 扩充 Pod CIDR 配置: 当前集群 Pod CIDR 已经用尽时，扩容节点启动 Pod 时会失败
    • 不能修改原有的地址段，需要新增地址段
    • 在 values.yml 中的 ipam.operator.clusterPoolIPv4PodCIDRList 列表中添加新的地址段
    • 重启 cilium operator kubectl rollout restart deployment/cilium-operator -n kube-system
