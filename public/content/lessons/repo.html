仓库服务#

容器镜像仓库#

  • 部署 Registry 提供容器镜像服务, 作为缺省镜像仓库
  • [备选] 部署 Harbor 提供容器镜像服务

两者部署其一即可, 不需要同时部署.

Registry (缺省) Harbor (备选)
组件构成 registry:3.0.0 + docker-registry-ui, 单 Deployment + 单 PVC core / jobservice / portal / registry + PostgreSQL + Redis
认证 htpasswd Basic Auth, 单一账号池 用户 / 项目 / 角色 RBAC, 可对接 LDAP, OIDC
多租户 无项目隔离, 登录账号默认可 pull / push / delete 项目级权限与配额
上游镜像代理 不支持, 需要逐个手工同步镜像 支持 proxy cache, 可代理 docker.io / gcr.io / nvcr.io 等
漏洞扫描 / 签名 无 支持 Trivy 扫描与镜像签名 (模板中 trivy.enabled 缺省关闭)
仓库间复制 无 支持, 可用于跨机房分发
保留策略 / 审计日志 无 支持
资源开销 低 高, 生产环境建议外接 PostgreSQL 与 Redis

缺省选 Registry: 单集群内部使用, 账号可控, 只需要 push / pull / delete.

换成 Harbor 的场景:

  • 需要多团队或多项目隔离与 RBAC, 并对接 LDAP / OIDC 统一认证
  • 需要上游镜像代理缓存 (proxy cache), 替代逐个手工同步上游镜像
  • 需要漏洞扫描, 镜像签名, 保留策略或跨机房复制
  • 需要统一托管 Helm Chart 等 OCI 制品

镜像 P2P#

  • 缺省在 base 阶段部署 Spegel 提供镜像 P2P 服务
  • [备选] 部署 Dragonfly 提供镜像 P2P 服务

两者部署其一即可. 如果 base 阶段已部署 Spegel, 改用 Dragonfly 前先卸载 Spegel.

Spegel (缺省) Dragonfly (备选)
部署位置 base/spegel, 随基础服务一起部署 repo/dragonfly, 按需单独部署
组件构成 单 DaemonSet manager / scheduler / seed client / client + MySQL + Redis
原理 节点间互为镜像源, 复用 containerd 本地已有镜像层, 无中心节点 独立 P2P 网络, 由 seed client 统一回源
支持的运行时 仅 containerd containerd, Docker, CRI-O 等
预热 (preheat) 不支持, 只能命中集群内已拉取过的层 支持, 首次拉取也能加速
分发对象 容器镜像 容器镜像, 以及模型权重, 数据集等任意文件
节点侧依赖 kubespray 设置 containerd_discard_unpacked_layers: false 由 client.dfinit 改写节点 containerd 配置
资源开销 低 高, 生产环境建议外接 MySQL 与 Redis

缺省选 Spegel: 集群使用 containerd, 加速的是同一镜像在多节点间的重复拉取.

换成 Dragonfly 的场景:

  • 需要预热: 大规模并发拉取新镜像时首次拉取也要加速, 例如推理服务扩容或训练任务启动
  • 需要分发非镜像文件, 例如模型权重, 数据集
  • 节点运行时不是 containerd
  • 需要跨集群或跨机房的 P2P 调度与流量统计
