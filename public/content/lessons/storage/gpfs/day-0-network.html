GPFS 网络#

介绍#

  • 为什么使用 RDMA
    • 直接移动数据，避免数据复制和上下文切换
    • 节省CPU周期，让DMA引擎完成工作，绕过内核
    • 收敛：单一网络支持存储和计算, 主要在 HPC 场景
    • RDMA: Remote Direct Memory Access
    • 目标：高性能网络
      • Low latency
      • High throughput
  • 传统TCP/IP与RDMA协议栈对比
  • GPFS 支持 RDMA 网络
    • 支持 IB 和 RoCE
    • 引入以支持批量数据（verbsRdma）
    • 也可以通过RDMA（verbsRdmaSend）将守护进程发送到守护进程的RPCs
    • RDMA 是 GPFS 集群节点之间页面池（pagepool）进出的传输方式。
    • 守护进程网络始终需要 TCP/IP（可能是 IPoIB）
    • 稳健性
      • 支持从 RDMA 回退到 TCP/IP
      • RDMA 超时请求检测
    • 健康监测

配置#

  • 控制面网络
    • daemon-interface 使用创建节点时 hostname 或者 ip
      • 初始连接建立和 fallback
      • 心跳，lease，token 和 RPC 通信
      • TCP 通信配置 subnets 则初始连接建立后使用 subnets 的 IP 地址
      • RDMA 配置 verbsRdmaSend=yes 则使用 RDMA
    • admin-interface 缺省继承 daemon-interface
      • 用于集群管理命令执行, 通常走 ssh 协议
  • RDMA 配置
    • verbsRdma = [yes|no]
      • 是否启用 RDMA (IO 通信走 RDMA)
      • 缺省为关闭 (支持 RDMA 必须开启)
    • verbsPorts = <device>/<port>/<fabric>/<service level>
      • 要使用的 RDMA 端口列表
      • 可以指定多个设备，使用空格分隔，例如 verbsPorts = "mlx5_2/1 mlx5_3/1 mlx5_4/1 mlx5_5/1"
    • verbsRdmaSend = [yes|no]
      • 启用 RDMA Send 以用于发送和接收 RPC (控制走 RDMA)
      • 缺省为关闭
        • yes: 守护进程也走 RDMA，性能更好
        • no: 守护进程走 TCP/IP，超大规模集群稳定性更好
          • 在 500 节点以上不要启用
    • verbsRdmaCm = [yes|no]
      • 是否启用 RDMA Connection Manager (RDMA_CM) API 来建立和管理 RDMA 连接
      • 缺省为关闭 (支持 RoCE 必须开启)
    • 配置示例
# 修改配置
mmchconfig verbsRdma=enable,verbsRdmaSend=yes,verbsPorts="mlx5_2/1 mlx5_3/1 mlx5_4/1 mlx5_5/1",verbsRdmaCm=enable

# 重启集群
mmshutdown -a && mmstartup -a
# 等待所有节点状态为 active
mmgetstate -a

# 查看 RDMA 是否开启
mmfsadm test verbs status
# 测试 RDMA 连接状态
mmfsadm test verbs conn
# 查看网络状态
mmdiag --network
  • TCP 配置
    • GPFS 5.1.5 支持 TCP 多轨通信 (MROT), 可以并发使用多个子网和多个物理接口
    • subnets = "<subnet1> <subnet2> ..."
      • 支持多个 subnet 之间负载均衡和故障转移
      • 如何未设置 subnet 则使用 daemon IP
      • 2 节点间 TCP 通信必须属于 subnets 配置内的, 否则回退 daemon interface 通信
    • maxTcpConnsPerNodeConn = <number>
      • 缺省值为 2
      • 多 interface 时，必须大于或等于 interface 数量
      • 对于 Bonding 设备，增大此值以提高性能
      • Episode 17: Spectrum Scale MCOT
      • multi-connection over TCP (MCOT): tuning may be required
    • 配置示例
# 网络配置：
# * 每个 interface 分配 4 个 conns
# * 使用 remotecluster 时
#   * 在每个集群上均需要配置互相连接的集群网段
#   * 每个网络后需要添加后缀描述集群名称
# 不同网段集群配置示例：
# * 一个集群
mmchconfig subnets="10.24.1.0 10.24.2.0 10.24.3.0 10.24.4.0",maxTcpConnsPerNodeConn=16
# * 客户端和存储集群不在相同段，每个段后缀描述集群名称
mmchconfig subnets="10.24.1.0/gpfs1.example.com 10.24.2.0/gpfs1.example.com 10.24.3.0/gpfs1.example.com 10.24.4.0/gpfs1.example.com 10.24.5.0/client1.example.com 10.24.6.0/client1.example.com",maxTcpConnsPerNodeConn=16
# * 客户端和存储集群在相同段, 集群名称不相似
mmchconfig subnets="10.24.1.0/gpfs1.example.com;client1.example.com 10.24.2.0/gpfs1.example.com;client1.example.com 10.24.3.0/gpfs1.example.com;client1.example.com 10.24.4.0/gpfs1.example.com;client1.example.com",maxTcpConnsPerNodeConn=16
# 客户端和存储集群在相同段，集群名称相似性
mmchconfig subnets="10.24.1.0/gpfs[12].example.com 10.24.2.0/gpfs[12].example.com 10.24.3.0/gpfs[12].example.com 10.24.4.0/gpfs[12].example.com",maxTcpConnsPerNodeConn=16

# 重启集群
mmshutdown -a && mmstartup -a
# 等待所有节点状态为 active
mmgetstate -a

# 查看网络状态
mmdiag --network
