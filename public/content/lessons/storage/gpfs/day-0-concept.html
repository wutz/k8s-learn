GPFS 概念#

IBM Storage Scale (aka GPFS,aka IBM Spectrum Scale) started in 1998: IBM’s shared disk, parallel cluster file system.

模式#

  • 使用 SNC (shared nothing cluster) 模式

补充：Vast DASE 架构

多集群#

  • 每个集群独立管理
  • 每个集群拥有或者不拥有存储
  • 集群可以挂载远程集群的文件系统

  • 提供远程客户端集群的多租户功能
  • 定义哪些远程集群可以查看单个文件系统命名空间内的哪些文件集
  • 动态能力，使用mmauth允许或拒绝命令，授予或拒绝对远程集群的文件集访问权限
  • 配额和快照仅对授权的文件集可见，不是文件系统中所有的文件集
  • root fileset 根文件集的内容对所有客户端集群始终可见/可访问

访问#

  • POSIX
  • CES: NFS, SMB, S3 和 HDFS
  • CSI

版本#

  • 服务端集群全闪高性能必须安装 ECE 版本
  • 客户端集群可以安装 DAE 或者 DME (支持审计日志) 版本

集群#

服务组件：

  • Config Servers
    • 配置服务器，用于管理集群的配置
    • CCR
    • 不参与数据读写
  • Cluster Manager
    • 由仲裁选择
    • 一个集群只有一个
    • 管理租约，故障和恢复
    • 执行 mmlsmgr -c 查看
    • 选择 File Manager
  • File Manager
    • 每个文件系统一个
    • 管理文件系统配置
    • 空间分配
    • Quota 管理
    • 执行 mmlsmgr 查看
  • Token Manager
    • 令牌管理服务器通过授予令牌来协调对共享磁盘上文件的访问，这些令牌传递读取或写入文件数据或元数据的权限
    • 每个文件系统多个
    • 执行 mmdiag --tokenmgr 查看

节点角色：

  • Quorum node
    • GPFS 使用一种称为仲裁的集群机制，以便在节点发生故障时保持数据一致性
    • 如果由于节点故障而无法保持仲裁，那么 GPFS 会卸载剩余节点上的本地文件系统，并尝试重新建立仲裁，此时会发生文件系统恢复
    • GPFS 可以使用以下两种方法之一来确定仲裁:
      • 节点仲裁: 节点法定数是 GPFS 的缺省法定数算法
      • 使用仲裁盘的节点仲裁: 在小型 GPFS 集群上运行时，您可能希望集群在只有一个幸存节点的情况下保持联机状态. 仲裁磁盘必须连接到所有仲裁节点
    • 选择仲裁节点规则:
      • 对于单个恢复组，以下仲裁节点规则适用
        • 当 scale-out 节点数为 4 时，quorum 节点数设置为 3
        • 当横向扩展节点数为 5 或 6 时，仲裁节点数设置为 5
        • 当横向扩展节点数为 7 个或更多时，仲裁节点数设置为 7
      • 如果恢复组的数量大于 1 且小于或等于 7，那么 7 个仲裁节点将以循环方式分布在各个恢复组中
      • 如果恢复组的数量超过 7 个，则选择 7 个恢复组作为仲裁持有者
  • Manager node
    • 仲裁节点也是管理节点
    • 可以指派非仲裁节点作为管理节点
    • File Manager 会从 Manager node 中选择一个
    • Token Manager 会运行在多个 Manager node 上
  • Metanode
    • 每个打开的文件都有一个元节点 metanode
    • 第一个打开文件的节点成为 metanode
    • 在几乎所有情况下，持续打开文件时间最长的节点都是元节点
    • 所有访问文件的节点都可以直接读取和写入数据，但元数据的更新只能由元节点写入
    • 使用远程集群时
      • 多个客户端集群访问同一文件时，metanode 运行在存储集群上
      • mmchconfig preferDesignatedMnode=yes 只能强制 metanode 运行在 manager node 上, 通常与 token manager 运行在一起
      • 强制 metanode 运行在存储集群上的选项 mnodeRemoteAccessThreshold=0 不再被允许修改
    • 查看 metanode 信息
      • 执行 mmfsadm dump files |grep -E "inode |tmmgr|metanode" 查看运行节点(包含大量缓存 metanode)
      • 其中节点名称关系使用 mmdiag --network 查看
  • CES node
    • 导出 NFS,SMB,S3 和 HDFS 等协议

文件系统#

  • Disk: 物理磁盘, 例如 SSD 或者 HDD
  • Pdisk: 物理磁盘抽象, 代表一块实际物流磁盘
  • NSD: Network Shared Disk
    • 提供了一种通过网络实现块级接口的协议
  • Pool
    • 把性能，成本和可靠性的磁盘逻辑分组
      • system pool (必须）： 常用于 metadata 存储
      • data pool (可选，多个）: 常用于 data 存储, 根据存储介质不同分为多个 pool
      • external pool (可选): 连接外部对象存储等
    • 实现分层存储 ILM
  • Fileset
    • namespace 虚拟化
    • 子目录树
      • 相对于文件系统，用于细粒度控制, 例如空间限制和快照等
    • independent fileset 独立文件集: 使用独立 inode 空间
      • 为每个 inode space 分隔 inode 限制

GNR 架构#

GNR 概念#

  • RG: Recovery Group
    • 一组 pdisk 和 server
      • ESS: 2 台, 每台 IO Server 主控一个 RG 接管一半 Disk，互为 backup
        • 2 个 RG 实现 active-active 负载均衡, 性能最大化
      • ECE: 一个 RG 包含 3-32 台服务器
    • 每个 RG 内的服务器配置必须完全相同
    • 定义故障域和容错边界，RG 之间完全独立
    • 一个 RG 多个 DA
  • DA: Distributed Array 去中性化阵列
    • 磁盘 pdisk 相同类型(速度和容量)的组成一个 DA
    • 重建速度快
      • 传统 RAID 只有少量盘参与（例如 8+2 块）故障数据重建，重建速度慢
      • DA 所有盘参与重建，重建速度快
    • 一个 DA 包含多个 vdisk
  • vdisk
    • 精细分层和不同保护策略
      • 热数据 vdisk 使用 NVMe SSD
        • metadata 使用 4 副本
        • data 使用 8+3 纠删码
      • 冷数据 vdisk 使用 HDD
      • 不同 vdisk 可以使用不同 block size，RAID code 和 spare 数量
    • 每个 vdisk 对应一个 NSD
  • vdisk set
    • 多个 vdisk 组成 vdiskset 用于批量管理
    • 一个 vdisk set 可以使用多个 RG，但每个 RG 的硬件配置必须相同
    • 每个 RG 最大只能创建 512 个 vdisk
      • 一个 vdisk set 每个节点分配 2 个 vdisk
      • 一个 RG 内节点越多则可以创建 vdisk set 越少 ，例如 10 节点只能创建 24 个 vdisk set
        • 每个 RG 内可创建的 vdisk set 数量计算公式为 (512-1)/(2*node)-1 (向下取整)
        • 参见 vdisks
