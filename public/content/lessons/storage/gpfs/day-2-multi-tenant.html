GPFS 多租户#

GPFS 支持 3 种粒度的多租户实现方案，分别适合不同的容量需求、CSI 支持要求和交付周期。

方案对比#

方案 隔离粒度 适用客户 起步容量 交付周期 原生 GPFS CSI Metadata 隔离
每个租户一个存储集群 物理集群 容量需求大（500T 以上）、需要完善 CSI 支持的重要客户 500T 以上 3-7 天 支持 物理隔离
每个租户一个文件系统 文件系统 容量相对不大（50T 以上）、可接受第三方 CSI 的重要客户 50T 起步/步长 1 天以内 需第三方工具 共享磁盘，有竞争
每个租户一个文件集 文件集 fileset 任意容量、接受第三方 CSI、可接受元数据性能不稳定的中小客户 任意 0.5 天以内 需第三方工具 共享磁盘，竞争严重

Scale 不支持对 Metadata IOPS 进行 QoS 限制，因此除物理集群隔离外，其余两种方案在多租户/多用户场景下均存在 Metadata 性能竞争，参见 GPFS 管理 - QoS 管理。

各方案优劣势#

每个租户一个存储集群#

  • 优势：性能完全物理隔离；提供的功能支持最完整。
  • 劣势：
    • 起步容量大（一般在 500T 以上），如果用户不需要这么多容量会导致容量空置；
    • 建设周期通常在 3-7 天，影响交付进度；
    • 此类存储集群过多后，导致交付人员严重不足。

每个租户一个文件系统#

  • 优势：
    • 可以按照 50T 起步或步长来满足用户低容量需求；
    • 在存储集群已经建设好的情况下，交付周期通常在 1 天以内。
  • 劣势：
    • 50T 步长仍然不能满足一些更低容量用户的需求；
    • 由于 GPFS 不支持 Metadata QoS，多个租户元数据服务共享相同底层磁盘，存在竞争磁盘情况；
    • Quota 设置只能在拥有集群上设置，这依赖拥有集群管理员，通常是瓶颈，此时需要开发第三方工具来改善；
    • GPFS GUI 的 CSI 权限不能按照 fs 纬度控制，导致不能直接使用原生 GPFS CSI，此时需要功能弱的第三方 CSI。

每个租户一个文件集#

  • 优势：
    • 可以按照任意容量大小满足用户各种需求；
    • 在存储集群已经建设好的情况下，交付周期通常在 0.5 天以内。
  • 劣势：
    • root fileset 空间不隔离，可能导致用户误用或者滥用，可以设置 root fileset QoS 缓解；
    • 由于 GPFS 不支持 Metadata QoS，元数据性能存在竞争情况，特别是写类别性能基本多个租户间完全靠抢；
    • Quota 设置只能在拥有集群上设置，这依赖拥有集群管理员，通常是瓶颈，此时需要开发第三方工具来改善；
    • GPFS GUI 的 CSI 权限不能按照 fs 纬度控制，导致不能直接使用原生 GPFS CSI，此时需要功能弱的第三方 CSI。

每个租户一个存储集群#

适合容量需求大（500T 以上）、GPFS CSI 支持完善的重要客户。

  1. 按照标准 GPFS 集群建设，使用 remote cluster 特性。每个租户拥有独立的存储集群（拥有集群），客户端集群（访问集群）通过 remote cluster 挂载。
    • 存储集群部署参见 GPFS 存储集群部署
    • 客户端集群部署与远程挂载参见 GPFS 客户端集群部署与挂载
  2. 需要 GPFS CSI 时，分别在 2 个集群上各自安装 GPFS GUI 服务。
    • GUI 部署参见 GPFS GUI 部署
    • CSI 部署参见 GPFS CSI

由于每个租户独享物理集群，性能完全隔离，且可直接使用原生 GPFS CSI（按集群纬度授权 GUI），功能支持最完整。

每个租户一个文件系统#

适合容量相对不大（50T 以上）、能接受第三方 CSI 的重要客户。

在同一个存储集群内，为每个租户创建独立的文件系统，通过 remote cluster 仅授权对应文件系统。

创建文件系统#

受 GPFS ECE vdisk 512 个数量限制（参见 GPFS 概念 - vdisk set），通常每个文件系统起步或者步长为 50T。

# 创建元数据与数据混合的 vdisk set，每个 50T，需要更多容量时创建多个
# --set-size 参数可以指定百分比（如：90%）也可以指定大小（如：50T）
mmvdisk vs define --vs t1vs1 --rg RG1 --code 8+3P --bs 4M --da DA1 --nsd-usage dataAndMetadata --sp system --set-size 50T
mmvdisk vs create --vs t1vs1
mmvdisk vs list --vs all

# 使用 vdisk set 创建租户需要的文件系统
mmvdisk fs create --fs t1fs --vs t1vs1 --mmcrfs -T /t1fs
mmchfs t1fs --auto-inode-limit
mmchfs t1fs --perfileset-quota
mmchfs t1fs --filesetdf
mmchfs t1fs -Q yes
mmmount t1fs -a

需要更多容量时，定义并创建多个 50T 的 vdisk set，再通过 mmvdisk filesystem add 加入文件系统扩容，参见 GPFS 存储集群部署 - 文件系统扩缩容。

授权远程访问指定文件系统#

设置 remote cluster 只允许访问指定 fs。在存储集群（拥有集群）上执行：

# 添加租户客户端集群的 GPFS 公钥
mmauth add tenant1.example.com -k id_rsa.pub

# 仅授予该租户对 t1fs 文件系统的读写权限
mmauth grant tenant1.example.com -f t1fs -a rw

完整的远程挂载流程参见 GPFS 客户端集群部署与挂载 - 远程挂载存储集群的文件系统。

Quota 设置#

裸机使用设置 quota 时，需联系拥有集群管理员在拥有集群上设置（Quota 只能在拥有集群上设置）：

# 该租户独占整个文件系统（数据均在 root 文件集），对 root 文件集设置 quota 即可限制总用量
# 设置大小软限制 45T，硬限制 50T
mmsetquota t1fs:root --block 45T:50T
mmlsquota -j root t1fs

对 root 用户施加 quota 限制，只需在租户的客户端集群（访问集群）上执行，无需拥有集群管理员介入：

mmchconfig enforceFilesetQuotaOnRoot=yes -i

如果在开启 enforceFilesetQuotaOnRoot 之前已经写入过数据，需要在拥有集群上执行 mmcheckquota t1fs 重新核算配额用量，否则已有用量统计不准，可能出现无法写入的情况。

或借助第三方工具 wutz/mmapi 中的 mmctl 让租户自助设置（内测中）：

mmctl quota set ...
mmctl quota list ...

k8s CSI 支持#

  • 需要支持 k8s CSI 时，可以使用 rancher/local-path-provisioner 来满足需求，限制是不支持 quota 设置，具体使用参见本仓库 storage/local-storage（shared-fs storageClass）。
  • 如果需要原生 GPFS CSI 支持，由于 GPFS GUI 的 CSI 权限不能按 fs 纬度控制，需要借助第三方工具 wutz/mmapi 实现（内测中）。

每个租户一个文件集#

适合任意容量大小、接受第三方 CSI、元数据性能可能不稳定的中小客户。

在同一个文件系统内，为每个租户创建独立的文件集 fileset，通过 remote cluster 仅授权对应文件系统下的指定文件集。

防止 root fileset 滥用#

root fileset 空间不隔离，可能导致用户误用或者滥用。需要设置 root fileset QoS 为 1，防止滥用：

# 启用 QoS
mmqos filesystem enable fs0

# 对 root fileset 设置极低 QoS，限制其直接使用
mmqos class create fs0 --class fs0-root --fileset root
mmqos throttle create fs0 --pool all --class fs0-root --maxiops 1 --maxmbs 1
mmqos throttle list fs0

创建文件集并设置 Quota 与 QoS#

在存储集群（拥有集群）上执行：

# 创建独立 inode 空间的 fileset
mmcrfileset fs0 t1fset --inode-space new
mmlinkfileset fs0 t1fset -J /fs0/t1fset
mmlsfileset fs0

# 设置 fileset quota（大小软限制 95G，硬限制 100G；文件软限制 95K，硬限制 100K）
mmsetquota fs0:t1fset --block 95G:100G --files 95K:100K
mmlsquota -j t1fset fs0

# 设置 fileset QoS，限制该租户元数据/数据 IOPS 与带宽
mmqos class create fs0 --class fs0-t1fset --fileset t1fset
mmqos throttle create fs0 --pool all --class fs0-t1fset --maxiops 1000 --maxmbs 100
mmqos throttle list fs0

对 root 用户施加 fileset quota 限制，只需在租户的客户端集群（访问集群）上执行：

mmchconfig enforceFilesetQuotaOnRoot=yes -i
  • 如果在开启 enforceFilesetQuotaOnRoot 之前已经写入过数据，需要在拥有集群上执行 mmcheckquota fs0 重新核算配额用量，否则已有用量统计不准，可能出现无法写入的情况。
  • 由于 GPFS 不支持 Metadata QoS，元数据性能存在竞争情况，特别是写类别性能基本多个租户间完全靠抢。

授权远程访问指定文件集#

设置 remote cluster 只允许访问指定 fs 的 fileset。GPFS 通过传统的 mmauth 命令提供远程文件集访问控制（Remote Fileset Access Control），可定义远程集群在单个文件系统命名空间内能访问哪些文件集（参见 GPFS 概念）。

  • root fileset 根文件集的内容对所有客户端集群始终可见/可访问。
  • 配额和快照仅对授权的文件集可见，而非文件系统中所有文件集。

在存储集群（拥有集群）上执行：

# 添加租户客户端集群的 GPFS 公钥
mmauth add tenant1.example.com -k id_rsa.pub

# 仅授予该租户对文件系统 fs0 下文件集 t1fset 的读写权限
# --filesets 可指定多个文件集（逗号分隔），未授权的文件集对该租户不可见
mmauth grant tenant1.example.com -f fs0 --filesets t1fset -a rw

# 查看授权情况
mmauth show tenant1.example.com

如需调整或撤销对某个文件集的访问：

# 撤销该租户对文件集 t1fset 的访问
mmauth deny tenant1.example.com -f fs0 --filesets t1fset

完整的远程挂载流程参见 GPFS 客户端集群部署与挂载 - 远程挂载存储集群的文件系统。

Quota 设置#

裸机使用设置 quota 时，需联系拥有集群管理员（Quota 只能在拥有集群上设置），或借助第三方工具 wutz/mmapi 中的 mmctl（开发中）：

mmctl fileset create ...
mmctl quota set ...

k8s CSI 支持#

  • 需要支持 k8s CSI 时，可以使用 rancher/local-path-provisioner 来满足需求，限制是不支持 quota 设置，具体使用参见本仓库 storage/local-storage（shared-fs storageClass）。
  • 如果需要原生 GPFS CSI 支持，由于 GPFS GUI 的 CSI 权限不能按 fs 纬度控制，需要借助第三方工具 wutz/mmapi 实现（开发中）。
