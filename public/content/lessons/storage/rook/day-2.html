Rook 日常维护#

节点与 OSD 管理#

  • 新增节点按照 k8s 新增节点操作即可，如果新节点有空盘则可以自动加入集群

  • 新增 OSD 插入空盘会自动加入集群

    在集群初始化或者新增OSD的过程中，如果遇到无法添加OSD并且在rook-ceph-osd-prepare出现类似如下提示信息：

cephosd: skipping osd.0: "0c5f13e9-5cd3-4076-b35a-512433821949" belonging to a different ceph cluster "22e2d8b8-3c19-47fa-ac47-af67f0e6cfb2"

可以先参考README.md中的抹除磁盘部分进行操作，如果抹除后仍然不行可以修改cluster/cluster.yaml文件，新增cleanupPolicy.wipeDevicesFromOtherClusters=true配置 参考文档：

https://rook.io/docs/rook/latest-release/Getting-Started/ceph-teardown/?h=wipe#zapping-devices
https://rook.io/docs/rook/latest-release/CRDs/specification/?h=wipe#ceph.rook.io/v1.CleanupPolicySpec
  • 移除节点和 OSD
# 立即排干节点上的 pod 
kubectl drain sn-10-254-41-1 --ignore-daemonsets --delete-emptydir-data

# 如果需要撤销 drain 节点，则执行 uncordon 命令
#kubectl uncordon sn-10-254-41-1

# 删除节点
kubectl delete node sn-10-254-41-1
# 查看 OSD 列表, 找到移除节点下的 osd ids
kubectl rook-ceph ceph osd tree

# operator缩为0，防止在维护过程中被operator重新加入到集群
kubectl -n rook-ceph scale deployment rook-ceph-operator --replicas=0

# 将osd对应的deployment置为0，
kubectl -n rook-ceph scale deployment rook-ceph-osd-1 --replicas=0
kubectl -n rook-ceph scale deployment rook-ceph-osd-2 --replicas=0
kubectl -n rook-ceph scale deployment rook-ceph-osd-3 --replicas=0

# 进入到toolbox环境将osd状态置为down
toolbox> ceph osd down osd.1
toolbox> ceph osd down osd.2
toolbox> ceph osd down osd.3

# 删除 OSD, osd 必须处于 down 状态才允许移除
kubectl rook-ceph rook purge-osd 1,2,3 --force

# 【可选】如果创建集群时指定了useAllDevices=false，并且单独指定了storage的devices信息，需要将对应的节点和磁盘信息删除
kubectl -n rook-ceph edit cephcluster rook-ceph

# 回复operator
kubectl -n rook-ceph scale deployment rook-ceph-operator --replicas=2

  • 更换故障 OSD 磁盘

    参考地址： https://rook.io/docs/rook/latest-release/Storage-Configuration/Advanced/ceph-osd-mgmt/?h=osd#remove-an-osd

# 查看 OSD 列表, 找到移除节点下的 osd ids
kubectl rook-ceph ceph osd tree

# operator缩为0，防止在维护过程中被operator重新加入到集群
kubectl -n rook-ceph scale deployment rook-ceph-operator --replicas=0


# 将osd对应的deployment置为0，
kubectl -n rook-ceph scale deployment rook-ceph-osd-1 --replicas=0

# 查看 OSD 列表, 找到故障 OSD 的 id
kubectl rook-ceph ceph osd tree

# 进入到toolbox环境将osd状态置为down
toolbox> ceph osd down osd.1

# 更换故障 OSD 磁盘
kubectl rook-ceph rook purge-osd 1 --force

# 新增空盘自动加入集群，如果在cephcluster指定了设备，设备名称变更的话需要重新指定设备
# 恢复operator的副本数
kubectl -n rook-ceph scale deployment rook-ceph-operator --replicas=2
  • 节点离线缺省 30m 后开始 recovery 自动恢复满足数据冗余数量
