Weka 集群管理#

集群扩容#

前置条件：

  • 扩容的节点配置必须和之前节点完全一样
  • 安装 Weka 和初始化 OS 配置，参见 Weka 安装
# 删除默认容器
weka local stop default && weka local rm -f default

# 进入 Weka 部署工具包路径
cd /opt/tools/install

# 生成资源配置文件，参考部署集群时的配置文件 /opt/tools/install/config.json, 例如添加节点配置了 bond1 和 bond2
./resources_generator.py --path /tmp --net bond1/10.251.12.10/22 bond2/10.251.13.10/22 --compute-dedicated-cores 26 --drive-dedicated-cores 12 --frontend-dedicated-cores 2 --protocols-memory 20GiB

# 配置 join_ips 和 management_ips 为集群所有节点 IP, 参考部署集群时配置文件 /opt/tools/install/config.json
# * join_ips 指定现有集群前 5 个节点
# * management_ips 指定新节点 IP
options="--join-ips=10.251.12.4,10.251.13.4,10.251.12.5,10.251.13.5,10.251.12.6,10.251.13.6,10.251.13.7,10.251.12.7,10.251.12.8,10.251.13.8 --management-ips=10.251.12.10,10.251.13.10"
# 创建 drives 容器
weka local setup container --name drives0 --resources-path /tmp/drives0.json $options
# 创建 compute 容器
weka local setup container --name compute0 --resources-path /tmp/compute0.json $options
weka local setup container --name compute1 --resources-path /tmp/compute1.json $options
# 创建 frontend 容器
weka local setup container --name frontend0 --resources-path /tmp/frontend0.json $options

# 查看容器状态
weka local ps

# 查询新加节点 drives0 的 id, 例如查询到 49
weka cluster container
# 查询要添加盘的设备名称
grep path /tmp/drives0.json |awk -F\" '{print $4}' |xargs
# 以集群管理员登录在新节点
weka user login admin --org root
# 添加盘到集群中, 需要等待一段时间 
weka cluster drive add 49 /dev/nvme1n1 /dev/nvme19n1 /dev/nvme18n1 /dev/nvme17n1 /dev/nvme16n1 /dev/nvme15n1 /dev/nvme14n1 /dev/nvme13n1 /dev/nvme12n1 /dev/nvme11n1 /dev/nvme10n1 /dev/nvme0n1
# 查询添加进度
weka cluster drive |grep sn-10-254-41-10

# 查询集群状态，等待 REDISTRIBUTING 完成
weka status

扩容集群后发生什么：

  • 数据会重新均衡，weka status 会显示 REDISTRIBUTING
  • 容量增加是即使完成的
  • 写入性能会即使提升，读取性能提升需要等待数据均衡完成

节点新增盘#

  • 每个节点新增同样数量和规格盘
# 扫描新盘
weka cluster drive scan

# 列出未加入集群的盘
nvme list

# 添加盘到集群中
weka cluster drive add <container-id> <device-path1> <device-path2> ...

# 查询添加进度
weka cluster drive
weka status

集群缩容#

  • 移除节点前，集群必须处于 OK 状态
  • 每次移除一个节点，等待数据均衡完成后再移除下一个节点
# 查询指定节点所有 containers id
weka cluster container -F hostname=sn-10-254-41-4

# 停用指定 containers
weka cluster container deactivate 0 10 16 18

# 查询停用后节点 containers 进入 INACTIVE 状态 
weka cluster container -F hostname=sn-10-254-41-4
# 其中 drive 容器需要等待较长时间进入 INACTIVE 状态 (需要等待数据均衡完成), 可以查指定节点的 drive 状态
weka cluster drive -F hostname=sn-10-254-41-4

# 最后移除 containers
weka cluster container remove 0
weka cluster container remove 10
weka cluster container remove 16
weka cluster container remove 18

节点移除盘#

  • 每个节点移除同样数量和规格盘
# 查看 SSD 信息
weka cluster drive

## 每次只移除一个节点 SSD，等待重建完成再移除另外节点
# 停用指定 drive
weka cluster drive deactivate <id1/uuid1> <id2/uuid2> ...
# 或者移除指定 drive
weka cluster drive remove <uuid1> <uuid2> ...

# 查看重建进度, status 必须为 OK 才表明重建完成
weka status
---
status: REDISTRIBUTING (24 backend containers UP, 54/144 drives UP)
                Data redistribution in progress (23.9081%
---

集群故障容忍#

  • 在配置 EC X+2 情况下
  • 最大同时容量 2 节点或者 2 盘离线
  • 如果同时出现离线 3 个时，集群 IO 暂停，需要让 3 个恢复上线后，集群 IO 恢复
