Weka 分层存储#

概念#

  • 小于 1M 文件会被合并为大对象(大约 1M)上传对象存储
  • 大文件会被拆分为 8/16/32/64M 对象上传对象存储
  • 文件组主要设置分层策略
    • 保留策略 (Drive Retention Period): 文件最后变更或者访问后在 SSD 保留时间，缺省时间 1 天
    • 分层提示策略 (Tiering cue policy): 文件最后变更后等 “分层提示策略时间” 后会上传到对象存储，缺省时间 15 分钟
    • 保留策略至少是分层提示策略时间 3 倍大小
  • 如果读取数据不在 SSD 上，则需要从对象存储上读取, 并重新执行上面分层策略
  • 如果 SSD 已满，但是数据还未卸载到对象存储，则会背压到对象存储上性能下降
  • 每个元数据占用 4k 并总是存放在 SSD 上, 并且统计在 df -h 中(即占用文件系统总空间)，但 du -sh 不统计元数据大小

配置#

  • 添加对象存储：Manage -> Object Stores -> Create，推荐每个文件系统对应一个 Bucket
  • 附加对象存储到文件系统上：Mange -> Filesystems -> Attach Object Store Bucket, 选择对应对象存储然后保存
  • 修改文件系统大小：Manage -> Filesystems -> Edit -> Tiering -> Total Capacity

移除#

  • Manage -> Filesystems -> Deattach, 选择文件系统大小变为 SSD 大小
