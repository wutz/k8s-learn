Weka Linux 下使用#

安装客户端#

# 安装客户端
curl http://10.254.41.4:14000/dist/v1/install | sh

# 创建挂载点
mkdir /share

# 使用有挂载权限用户 ds1mount 登录到组织 deepseek1
weka user login ds1mount --org deepseek1 -H 10.254.41.4

# 挂载: 需要等待拉取镜像和安装依赖; num_cores 是物理网卡 2 倍，如果需要高性能 IOPS/MD 则需要设置 4 倍
# 客户端单个 IP, 使用 DPDK 独占 CPU 核
mount -t wekafs -o num_cores=4 -o net=bond1 10.254.41.4,10.254.41.5,10.254.41.6/ds1fs1 /share
# 客户端多个 IP, 使用 DPDK 独占 CPU 核
mount -t wekafs -o num_cores=8 -o net=bond1,net:ha=bond2 -o mgmt_ip=10.251.12.1+10.251.13.1 10.254.41.4,10.254.41.5,10.254.41.6/ds1fs1 /share
# [不推荐] 不使用 DPDK 独占 CPU 核，而是与 kernel 共享核, 性能慢 5 倍
mount -t wekafs -o num_cores=4 -o net=udp 10.254.41.4,10.254.41.5,10.254.41.6/ds1fs1 /share

# 查看挂载
df -h

# 卸载
umount /share

quota 管理#

# 使用组织管理员 ds1admin 登录, 注意组织管理员拥有删除文件系统权限
weka user login ds1admin --org deepseek1

# 已有目录设置 quota, 如果目录存在大量文件需要等待一段时间完成设置
weka fs quota set <dir> --hard 100GiB

# 查询 quota, 不指定只显示超出配额的配置
weka fs quota list --all
# 查询 quota，普通权限即可查询
df -h <dir>

# 重制目录配额
weka fs quota reset <dir>

启用数据服务#

启用数据服务后，在已存在大量文件的目录开启 quota 时，执行设置 quota 命令不需要等待扫描即可完成设置，会由数据服务后台执行

  • 只有启用 dataserv 服务，GUI 中创建 quota 按钮才会出现
# 在 root 组织下创建文件系统 .config_fs 大小 200GB，并且开启认证
weka fs add .config_fs default 200GB --auth-required yes

# 设置数据服务全局配置
weka dataservice global-config set --config-fs .config_fs

# 启动数据服务用于后台 quota 扫描, 其中 --join-ips 指定任意管理 ip
weka local setup container --name dataserv0 --base-port 14500 --join-ips 10.251.12.4  --only-dataserv-cores --allow-mix-setting

# 查看数据服务进程
weka local ps

快照管理#

  • 快照开销只有变化的内容，最小粒度是 4k
  • 集群的最大同时是读快照 24,576 个, 最大同时是写快照 14,336 个
  • 集群可以同时有只读和可写快照，但是可写快照消耗资源是只读快照 2 倍
# 为文件系统 ds1fs1 创建快照 snap1, 新建快照存放在根的 .snapshots 目录下 (必须 cd .snapshots 访问)
weka fs snapshot add ds1fs1 snap1 

# 查看快照
weka fs snapshot ds1fs1

# 从快照恢复文件系统
weka fs restore ds1fs1 snap1

# 移除快照
weka fs snapshot remove ds1fs1 snap1
