部署 Ceph RGW 对象存储#

创建 Realm, ZoneGroup 和 Zone#

Ceph RGW 默认提供 default ZoneGroup 和 Zone。 为了防止用户间的操作互相影响，考虑通过创建不同 Zone 实现 RGW 的隔离。

以创建 s3-rgw1 为例:

# 创建 Realm
radosgw-admin realm create --rgw-realm=s3-rgw1 

# 创建 ZoneGroup
radosgw-admin zonegroup create --rgw-zonegroup=s3-rgw1 --rgw-realm=s3-rgw1 --master 

# 创建 Zone
radosgw-admin zone create --rgw-zonegroup=s3-rgw1 --rgw-zone=s3-rgw1  --master 

# 更新配置
radosgw-admin period update --commit

创建 Pool#

以创建 s3-rgw1 Zone 的存储池为例:

# 创建索引池
ceph osd pool create s3-rgw1.rgw.buckets.index rep_ssd
ceph osd pool application enable s3-rgw1.rgw.buckets.index rgw

# 创建数据池
ceph osd pool create s3-rgw1.rgw.buckets.data erasure ec42_hdd --bulk
ceph osd pool application enable s3-rgw1.rgw.buckets.data rgw

# 创建用于存放分段上传的文件数据池
ceph osd pool create s3-rgw1.rgw.buckets.non-ec rep_hdd
ceph osd pool application enable s3-rgw1.rgw.buckets.non-ec rgw

部署 RGW#

  • 编写 s3-rgw1 Zone 配置文件
# 创建文件 s3-rgw1.yaml
service_type: rgw
service_id: s3-rgw1
placement:
  host_pattern: sn*
  count_per_host: 2
networks:
  - 10.128.0.0/16
spec:
  rgw_realm: s3-rgw1
  rgw_zone: s3-rgw1
  rgw_frontend_port: 8000

  • 由于设置实例数为 2， 这将占用系统端口 8000-8001, 如果有多个Zone需要配置RGW，则端口不能冲突。其他Zone可以指定8002-8003端口，以此类推

  • networks 设置对外提供服务的网络，一般与 Public 网络一致

  • 部署 s3-rgw1 RGW 服务

ceph orch apply -i s3-rgw1.yaml

ceph orch ls
# 查询 RGW 进程
ceph orch ps --service_name rgw.s3-rgw1

# 将 RGW 的控制池设置为 SSD 副本
ceph osd pool set .rgw.root crush_rule rep_ssd

# 将日志、控制和元数据池设置为 SSD 副本。不同 Zone 需要分别设置
ceph osd pool set s3-rgw1.rgw.log crush_rule rep_ssd
ceph osd pool set s3-rgw1.rgw.control crush_rule rep_ssd
ceph osd pool set s3-rgw1.rgw.meta crush_rule rep_ssd
  • 开启rgw性能监控数据。不开的话Grafana RGW S3 Analytics 页面没有数据
# 开启使用情况日志记录
ceph config set client.rgw rgw_enable_usage_log true

# 开启操作日志记录（Analytics 依赖此数据源）
ceph config set client.rgw rgw_enable_ops_log true

# 设置日志保留策略（防止撑爆 Rados 存储池，建议保留 7 天）
ceph config set client.rgw rgw_usage_log_tick_interval 30
ceph config set client.rgw rgw_usage_log_flush_threshold 1024

# 开启clieng.rgw 的用户和同级别性能统计
ceph config set client.rgw rgw_bucket_counters_cache true
ceph config set client.rgw rgw_user_counters_cache true

# 查看rgw开头的服务名称，这里举例是rgw.s3-rgw1
ceph orch ls

# 重启所有rgw实例生效
ceph orch restart rgw.s3-rgw1

  • rgw 监控数据只保留7天

    设置操作系统定时任务，以下为清理脚本/usr/local/bin/rgw_trim_usage.sh

#!/bin/bash
# 计算 7 天前的时刻
END_DATE=$(date -d "7 days ago" +"%Y-%m-%d 00:00:00")
# 执行清理并记录简单日志
/usr/bin/radosgw-admin usage trim --end-date="$END_DATE"
echo "$(date): Trimmed RGW usage logs older than $END_DATE" >> /var/log/ceph/rgw_usage_trim.log

定时任务

crontab -e
# 每天凌晨 2:00 执行一次
0 2 * * * /usr/local/bin/rgw_trim_usage.sh

部署 Ingress 服务#

  • 仅支持 http 部署
# 创建文件 ingress-s3-rgw1.yaml
service_type: ingress	      # 服务的类型。这里写死ingress
service_id: rgw.s3-rgw1 # 服务的唯一id。这里设置的id不要与现有的冲突。可以通过ceph orch ls查看现有的service_id
placement:
  host_pattern: sn*	      # ingress服务部署的主机正则表达式。参考 https://docs.ceph.com/en/latest/cephadm/services/rgw
spec:
  backend_service: rgw.s3-rgw1 # 参考rgw部署的service_id。不同Zone对应的backend_service不同。
  virtual_ips_list:         # 部署的VIP列表。VIP列表成员个数与部署的节点个数一致。每个节点会分配一个VIP。
  - 10.128.0.151/16
  - 10.128.0.152/16
  - 10.128.0.153/16
  - 10.128.0.154/16
  first_virtual_router_id: 150  # keepalived服务的唯一起始router_id。每个VIP会有自己的一个router_id，每个router_id累计加1。比如有4个VIP，则router_id依次为150、151、152、153
  frontend_port: 8082        # 最终暴露的对外服务的端口
  monitor_port: 1967        # 监控端口，相同主机如果部署了多个ingress实例需要设定不同的端口。

其中 vip 列表从管理员获取, 为了最大化负载均衡效果，一般与节点数量一致

  • 仅支持 https 部署【可选】

    如果需要使用 https 则需要配置 ssl_cert 和 frontend_port 为 443

    区分Zone参考http的配置。

service_type: ingress
service_id: rgw.s3-rgw1
placement:
  host_pattern: sn*
spec:
  backend_service: rgw.s3-rgw1
  virtual_ips_list:
  - 10.128.0.151/16
  - 10.128.0.152/16
  - 10.128.0.153/16
  - 10.128.0.154/16
  first_virtual_router_id: 150
  frontend_port: 443
  monitor_port: 1967
  ssl_cert: |                         
    -----BEGIN CERTIFICATE-----
    ...
    -----END CERTIFICATE-----
    -----BEGIN PRIVATE KEY-----
    ...
    -----END PRIVATE KEY-----

使用#

创建用户#

# 创建用户
radosgw-admin user create --uid=wutz --display-name="Taizeng Wu" --rgw-realm=s3-rgw1

# 查询用户
radosgw-admin user info --uid=wutz --rgw-realm=s3-rgw1

# 删除用户
radosgw-admin user rm --uid=wutz --rgw-realm=s3-rgw1

设置 quota#

# 按照用户设置 quota
# --max-size 单位可以使用 B/K/M/G/T
radosgw-admin quota set --uid=wutz --quota-scope=user --max-size=10G --max-objects=10240 --rgw-realm=s3-rgw1
radosgw-admin quota enable --quota-scope=user --uid=wutz --rgw-realm=s3-rgw1

# 查询 quota
radosgw-admin user info --uid=wutz --rgw-realm=s3-rgw1
# 查询用户使用情况
radosgw-admin user stats --uid=wutz --rgw-realm=s3-rgw1

设置存储桶最大动态分片数和没分片最大对象数#

# 启用桶的动态分片功能。默认为true
ceph config set client.rgw rgw_dynamic_resharding true
# 设置每个桶最大动态分片个数为 8009。这里必须为素数
ceph config set client.rgw rgw_max_dynamic_shards 8009  
# 每个分片保存的最大对象数。默认为100000
ceph config set client.rgw rgw_max_objs_per_shard 100000
# 通过rgw_max_dynamic_shards * rgw_max_objs_per_shard 可以计算出每个桶最大对象数。这是个软限制，超过也不会拒绝写入新的对象。
# 超过后会在ceph health detail 存在大对象警告
# 668 large objects found in pool 'default.rgw.buckets.index'
# 官方文档说明： https://www.ibm.com/docs/en/storage-ceph/7.1.0?topic=resharding-bucket-index-dynamically

为指定桶设置默认最大分片数#

# 为桶 sre 设置分片数
# 该设置防止桶的对象数达到一定规模自动触发动态分片机制，动态分片会导致所有对象请求卡主。
radosgw-admin bucket reshard --bucket sre --num-shards 8009

流控#

Ceph RGW支持基于rgw实例的的流控框架。其特点如下：

  1. Ceph RGW 实例流控默认以1分钟为一个数据评估窗口。
  2. 基于 RGW 实例的执行：限制是在每个 RGW 实例上执行的，而不是集群范围。
  3. 如果有 2 个 RGW 且期望限制为 10 ops/min，则应将每个 RGW 配置为 5 ops/min。
  4. 如果客户端请求负载在端点之间分布不均，所需的限制可能需要设得比预期更低。
  5. 限制交集：支持用户级别和桶级别的qos配置，必须同时满足用户级和桶级限制。如果超过其中任何一个限制，请求都将被拒绝。
  6. 无流量整形：被节流的请求会被立即拒绝 (503)，而不是排队等待。
  7. 无请求中途节流：带宽是在请求完成后计算的，而不是在进行过程中。超过限制的用户会进入“debt”状态（最大为限制的 2 倍），并在接下来的时间间隔偿还“debt”之前被阻止发起新请求。

最佳实践：

假设当前Ceph集群有10个RGW实例，希望为wutz用户配置最大读写使用带宽为1GB/s，则--max-read-bytes和--max-write-bytes 计算公式为

1 （GB/s） / 10 （RGW）* 60 (秒) = 6G * (1024^3) = 6442450944 Bytes

radosgw-admin ratelimit set --ratelimit-scope=user --uid=wutz --max-read-bytes=6442450944 --max-write-bytes=6442450944

假设当前Ceph集群有10个RGW实例，希望为wutz用户配置最大读写IOPS为 1000 ops/s，则--max-read-ops和--max-write-ops 计算公式为

1000 (ops/s) / 10 (RGW) * 60 (秒) = 6000 ops/s

radosgw-admin ratelimit set --ratelimit-scope=user --uid=wutz --max-read-ops=6000 --max-write-ops=6000

启用或关闭用户的QOS流控

# 启用
radosgw-admin ratelimit enable --ratelimit-scope=user --uid=wutz
# 关闭
radosgw-admin ratelimit diable --ratelimit-scope=user --uid=wutz

配置分层存储 (可选)#

如果对象存储存放大量小对象，缺省数据池使用 HDD 纠删码，这会带来空间放大和性能下降问题。

可以通过为不同对象大小选择不同的存储池来解决这个问题。

  • 小于 16K 对象，存放在副本池 SSD 上 (由于 SSD 空间可能有限，需根据可用 SSD 空间调整这个大小)
  • 16K - 1M 对象，存放在副本池 HDD 上
  • 大于等于 1M 对象，存放在缺省纠删码 HDD 上
# 创建大对象类 StorageClass
radosgw-admin zonegroup placement add \
    --rgw-zonegroup default \
    --placement-id default-placement \
    --storage-class LARGE_OBJ
# 创建中等对象类 StorageClass
radosgw-admin zonegroup placement add \
    --rgw-zonegroup default \
    --placement-id default-placement \
    --storage-class MEDIUM_OBJ

# 将数据池分配给不同的 StorageClass
radosgw-admin zone placement add \
	--rgw-zone default \
	--placement-id default-placement \
	--storage-class LARGE_OBJ \
	--data-pool default.rgw.buckets.data
radosgw-admin zone placement add \
	--rgw-zone default \
	--placement-id default-placement \
	--storage-class MEDIUM_OBJ \
	--data-pool default.rgw.buckets.mediumobj
radosgw-admin zone placement modify \
	--rgw-zone default \
	--placement-id default-placement \
	--storage-class STANDARD \
	--data-pool default.rgw.buckets.smallobj

# 创建小对象池使用 SSD 副本
ceph osd pool create default.rgw.buckets.smallobj rep_ssd 
ceph osd pool application enable default.rgw.buckets.smallobj rgw
ceph osd pool set default.rgw.buckets.smallobj target_size_ratio 0.7

# 创建中对象池使用 HDD 副本
ceph osd pool create default.rgw.buckets.mediumobj rep_hdd 
ceph osd pool application enable default.rgw.buckets.mediumobj rgw
ceph osd pool set default.rgw.buckets.mediumobj target_size_ratio 0.3
ceph osd pool set default.rgw.buckets.data target_size_ratio 0.7

# 重启 RGW
ceph orch restart rgw.default
# 创建 Lua 脚本
cat << 'EOF' > s3.lua
-- Lua script to auto-tier S3 object PUT requests

-- exit script quickly if it is not a PUT request
if Request == nil or Request.RGWOp ~= "put_obj"
then
  return
end

-- apply StorageClass only if user hasn't already assigned a storage-class
if Request.HTTP.StorageClass == nil or Request.HTTP.StorageClass == '' then
  if Request.ContentLength < 8192 then
    Request.HTTP.StorageClass = "STANDARD"
  elseif Request.ContentLength < 1048576 then
    Request.HTTP.StorageClass = "MEDIUM_OBJ"
  else
    Request.HTTP.StorageClass = "LARGE_OBJ"
  end
  RGWDebugLog("applied '" .. Request.HTTP.StorageClass .. "' to object '" .. Request.Object.Name .. "'")
end
EOF

# 将脚本应用于 RGW
radosgw-admin script put --infile=./s3.lua --context=preRequest
