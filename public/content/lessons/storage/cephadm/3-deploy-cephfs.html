部署 CephFS#

依赖 部署 Ceph 集群

简介#

CephFS 是一个构建在 Ceph RADOS 之上并且兼容 POSIX 标准的文件系统.

CephFS 提供一些功能:

  • 可扩展性
  • 共享文件系统
  • 多文件系统: 每个文件系统使用自己独立的 Pool 和 MDS
  • 高可用性
  • 可配置文件和目录的布局: 允许使用不同的 Pool 和文件条带模式
  • POSIX ACL
  • Quota: 支持到目录级别配额

组件#

  • Client: 用户空间的 ceph-fuse 或者内核空间的 kcepfs
  • MDS: 元数据服务

MDS#

  • Status: Active 或者 Standy (缺省只使用一个 Active MDS)
  • Fail: 当 Active MDS 不响应时, Mon 会等待 mds_beacon_grace 时间后, 如果还不响应则标记 MDS 为 laggy . 然后 Standy MDS 变成 Active 状态
  • Rank: 定义最大 Active MDS 数量用于分担元数据负载, max_mds 配置 rank 数量
  • Cache:
    • mds_cache_memory_limit 设置 MDS 使用内存大小 ceph config set global mds_cache_memory_limit 34359738368
    • mds_cache_size 设置 MDS 使用 inode 数量
  • Affinity: 配置偏好使用的 MDS, 通过设置 mds_join_fs 在 Standby MDS 上

部署#

  1. 调整 mds 缺省使用内存大小
ceph config set global mds_cache_memory_limit 34359738368
  1. 创建 2 个副本 Pool 分别用于 metadata 和 data
# 创建 metadata pool
ceph osd pool create cfs01_metadata 32 32 rep_ssd
# 查看 pool 信息
ceph osd pool get cfs01_metadata all

# 创建 data pool
ceph osd pool create cfs01_data 32 32 rep_ssd 
# (可选) 设置此 pool 预计大小，有助于 PG 数量分配到合理值, 如果后续主要使用 EC POOL 则不需要设置
ceph osd pool set cfs01_data target_size_bytes 200T
# 查看 pool 信息
ceph osd pool get cfs01_data all

# 查看 PG 自动缩放状态
ceph osd pool autoscale-status
  1. 创建 CephFS
# 创建 CephFS，名字为 cfs01
ceph fs new cfs01 cfs01_metadata cfs01_data

# 查看 CephFS
ceph fs ls
ceph fs get cfs01
  1. 部署 MDS 到节点上
# 部署 MDS 到 2 个节点
ceph orch apply mds cfs01 --placement="2 label:mds"

# 查看 MDS 状态
ceph mds stat
  1. 生成 Client 访问 Key
#ceph fs authorize cfs01 client.cfs01 / rw |sudo tee /etc/ceph/ceph.client.cfs01.keyring
# 生成的 client key 同时允许 k8s ceph csi 使用
ceph auth get-or-create client.cfs01 osd 'allow rw tag cephfs *=cfs01' mon 'allow r fsname=cfs01' mds 'allow rw fsname=cfs01' mgr 'allow rw' |sudo tee /etc/ceph/ceph.client.cfs01.keyring
chmod 600 /etc/ceph/ceph.client.cfs01.keyring
  1. 发送配置和 Key 到 Client
ssh client "mkdir /etc/ceph"
scp /etc/ceph/ceph.conf client:/etc/ceph
scp ceph.client.cfs01.keyring client:/etc/ceph
  1. 挂载
# Ubuntu 20.04 及以上
apt install ceph-common 

# RHEL/CentOS 7
cat > /etc/yum.repos.d/ceph.repo << 'EOF'

gpgkey=https://mirrors.tuna.tsinghua.edu.cn/ceph/keys/release.asc
EOF

cat > /etc/yum.repos.d/ceph.repo << 'EOF'

设置 quota#

参考：

  • https://docs.ceph.com/en/latest/cephfs/quota/
  • https://docs.ceph.com/en/latest/cephfs/client-auth/

如果需要设置 quota 则需要额外 p 权限。设置 quota 还会改变 df 大小与 quota 一致。

ceph fs authorize cfs01 client.cfs01p / rwp |tee /etc/ceph/ceph.client.cfs01p.keyring
chmod 600 /etc/ceph/ceph.client.cfs01p.keyring
scp ceph.client.cfs01p.keyring client:/etc/ceph
mount -t ceph :/ /share -o name=cfs01p,fs=cfs01

# 设置 10TiB 配额
setfattr -n ceph.quota.max_bytes -v 10995116277760 /share
getfattr -n ceph.quota.max_bytes /share
# 使用量
getfattr -d -m ceph.dir.* /share 
# 新 kernel 使用
getfattr -n ceph.dir.rbytes /share

添加 EC POOL#

# 创建 ec pool
# (推荐) 设置 bulk 标记，以最大 PG 数量分配，有助于利用更多 OSD 提升性能
ceph osd pool create cfs01_data_ec erasure ec42_ssd --bulk
# (可选) 设置此 pool 预计大小，有助于 PG 数量分配到合理值
ceph osd pool set cfs01_data_ec target_size_bytes 200T
# (必须) 设置此 pool 允许 EC 覆盖写
ceph osd pool set cfs01_data_ec allow_ec_overwrites true

# 添加 ec pool 到 cephfs 中
ceph fs add_data_pool cfs01 cfs01_data_ec

# 设置 layout 需要 p 权限见 quota 配置 (任意挂载节点执行一次)
setfattr -n ceph.dir.layout.pool -v cfs01_data_ec /share

修改纠删码配置（可选）#

注意： 本部分内容只是说明如何修改纠删码池的纠删码配置，默认不用执行

存储在创建初期可能由于节点个数的问题使用了纠删码配置ec22_ssd，后期随着节点的加入考虑到数据的安全性希望将纠删码配置修改为ec42_ssd。

注意： Ceph不支持对已存在的存储池修改纠删码配置，需要新建ec42_ssd纠删码存储池并加入到当前文件系统中，然后设定为默认存储池。

需要执行如下命令进行调整。

# 创建一个使用ec42_ssd纠删码的存储池
ceph osd pool create cfs01_data_ec42 erasure ec42_ssd --bulk
# (可选) 设置此 pool 预计大小，有助于 PG 数量分配到合理值
ceph osd pool set cfs01_data_ec42 target_size_bytes 200T
# (必须) 设置此 pool 允许 EC 覆盖写
ceph osd pool set cfs01_data_ec42 allow_ec_overwrites true

# 添加 ec pool 到 cephfs 中
ceph fs add_data_pool cfs01 cfs01_data_ec42

# 设置 layout 需要 p 权限见 quota 配置 (任意挂载节点执行一次)
setfattr -n ceph.dir.layout.pool -v cfs01_data_ec42 /share

注意：调整纠删码可能会导致该存储池进行数据的重新分配和平衡，执行期间可能会严重影响用户的使用体验。请谨慎执行该操作

调整文件系统参数#

# 最大文件大小调整到32TB
ceph fs set cfs01 max_file_size 35184372088832

使用 K8S PVC#

创建 subvolumegroup

ceph fs subvolumegroup create cfs01 csi

然后在 k8s 集群中按照 ceph-csi-cephfs 部署 ceph-csi 即可

自定义 MDS 缓存大小#

每个热 inode 大约占 3500 字节，需要根据实际情况调大 mds 缓存大小，否则会造成频繁回收引起元数据响应延迟过大

下面是设置指定文件系统 mds.cfs01 缓存大小为 64GiB

ceph config set mds.cfs01 mds_cache_memory_limit 68719476736

开启 MDS standby-replay 功能 （可选）#

注意： 该部分内容需要根据实际需要进行开启。

standby-replay功能使 standby 实例内存一直维护主的缓存，用于主 mds 故障快速恢复。

执行如下命令开启standby-replay功能

开启
ceph fs set cfs01 allow_standby_replay 1
关闭
ceph fs set cfs01 allow_standby_replay 0

开启后如果使用ceph fs status命令，输出与不开启有些差别

cfs01 - 3 clients
========
RANK      STATE                 MDS                ACTIVITY     DNS    INOS   DIRS   CAPS  
 0        active      cfs01.node01.bkyjmn  Reqs:  669 /s  6554k  5029k  3177    787k  
0-s   standby-replay  cfs01.node02.qwyzzn  Evts: 1196 /s  8113k  5028k  3177      0

开启后会多出0-s一行，该行用于展示standby的信息。不开启的情况下没有这行内容。

多 MDS (可选)#

  • 使用多个 mds 服务 一个 cephfs 可以分担请求压力，以及分散元数据缓存到不同的 mds 上
  • 为 HA，max_mds 数量必须小于 mds service 数量（即执行 ceph orch apply mds cfs01 --placement=3 数量）
# 关闭 mds balance （https://github.com/ceph/ceph/pull/52196/files）
ceph config set mds mds_bal_interval 0

# 静态均衡 /share/home 的子目录
setfattr -n ceph.dir.pin.distributed -v 1 /share/home

# 增加 mds 数量到 2
ceph fs set cfs01 max_mds 2
# 缩减 mds 数量到 1
ceph fs set cfs01 max_mds 1

# 查询
ceph fs get cfs01
ceph mds stat
ceph fs status

确认剩余空间#

有时需要确认文件系统可用空间好进行Ceph存储的下一步规划。

文件系统的可用空间与文件系统使用存储池的类型得盘率有直接关系。

存储池类型 存储池设定 得盘率 计算方法
副本池 2 副本 0.5 1/2
副本池 3 副本 0.33 1/3
纠删码池 2+2 0.5 2/4
纠删码池 4+2 0.67 4/6

假设cfs01文件系统默认使用2+2 纠删码池cfs01_data_ec，每个节点使用12块SSD磁盘，每块磁盘的大小为13.56TB，则cfs01文件系统可用空间计算方法为

# ceph df

--- POOLS ---
POOL                ID  PGS   STORED  OBJECTS     USED  %USED  MAX AVAIL
.mgr                 1    1   73 MiB       11  220 MiB      0    454 TiB
cfs01_data_ec        4  256      0 B        0      0 B      0    682 TiB

cfs01可用空间 = 682 TiB

如果允许1节点离线，还需要减去 (12 * 14) * 0.5 = 84 TiB 最后剩余 682 - 84 = 598 TiB

注意： 这里把13.56 向上进行了取整，也就是13.56 变成了 14 TiB

故障排除#

本章节主要描述日常遇到的一些CephFS问题及问题解决方法。

CephFS常见的问题包括响应缓慢、客户端操作卡主等。

CephFS响应缓慢#

本章节主要描述由于CephFS组件（MDS）造成的响应缓慢问题，请先确认你的单盘和OSD Pool性能没有问题。

获取CephFS MDS概要信息#

执行如下命令获取到指定CephFS的概要信息

root@mn01:~# ceph fs status cfs01
cfs01 - 96 clients
========
RANK  STATE             MDS                ACTIVITY     DNS    INOS   DIRS   CAPS
 0    active  cfs01.mn01.zxhhrq  Reqs:  2895 /s      30.6M  30.5M  1997k  21.5M
       POOL          TYPE     USED  AVAIL
cfs01_metadata  metadata   105G    114T
cfs01_data      data       80.6T   114T

96 clients表示已建立链接的客户端的数量。

cfs01.mn01.zxhhrq 表示CephFS cfs01的主MDS运行在mn01节点上。

DNS (Directory Number of Entries) 30.6M 表示文件系统中共计有 3050万个目录条目 (目录以及文件)，这个数字反映了 CephFS 中文件和目录的总数。

INOS 30.5M 表示inode的总数。

DIRS 1997k 表示文件系统中有 1997000 个目录。

CAPS 21.5M 表示已经授予给客户端的 capabilities 的数量。 高 CAPS 也意味着客户端对 CephFS 的活跃使用，如果CAPS的值大于等于 DNS的值可能存在MDS内存不够用的风险。

响应慢处理方案#

增加MDS主服务内存容量#

当发现MDS的CAPS值大于等于 DNS的值可能存在MDS内存不够用的风险后，可以尝试增加MDS服务的内存大小缓解当前遇到的问题。

# ceph config set mds.cfs01 mds_cache_memory_limit 68719476736

修改后时刻观察MDS服务的内存占用情况和响应情况。

驱逐客户端#

当文件系统客户端无响应或出现其他异常行为时，可能需要强制终止其对文件系统的访问。这个过程称为驱逐。

客户端可以自动驱逐（如果它们未能及时与 MDS 通信），或者手动驱逐（由系统管理员）。

客户端驱逐过程适用于所有类型的客户端，包括 FUSE 挂载、内核挂载、nfs-ganesha 网关以及任何使用 libcephfs 的进程。

在三种情况下，客户端可能会被自动驱逐:

  1. 在一个活动的 MDS 守护进程上，如果一个客户端超过 session_autoclose 秒（一个文件系统变量，默认为 300 秒）没有与 MDS 通信，那么它将被自动驱逐。
  2. 在一个活动的 MDS 守护进程上，如果一个客户端超过 mds_cap_revoke_eviction_timeout 秒（配置选项）没有响应 cap 撤销消息。 默认情况下，此功能处于禁用状态。
  3. 在 MDS 启动期间（包括故障转移时），MDS 会经历一个名为 reconnect 的状态。在此状态下，它会等待所有客户端连接到新的 MDS 守护程序。如果任何客户端未能在时间窗口（ mds_reconnect_timeout ，默认为 45 秒）内执行此操作，则它们将被驱逐

通过如下命令获取到客户端id

ceph tell mds.cfs01.mn01.zxhhrq client ls

[
    {
        "id": 205000,
        "entity": {
            "name": {
