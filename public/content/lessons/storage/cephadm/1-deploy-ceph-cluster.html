1.1.3 安装 Cephadm 用于部署集群#

1.1.8 配置优化参数#

1.1.8.1 256GB内存OSD RocksDB参数优化#

对于256GB内存的节点，OSD占用的总内存最好控制在192GB以内。

这样32盘每OSD最大占用内存6GB；24盘每OSD最大占用内存8GB。分给OSD底层RocksDB数据库的内存最大2GB。

这样反推出： 2GB = max_write_buffer_number (8) * write_buffer_size (256MB)

# 调整RocksDB配置
ceph config set osd bluestore_rocksdb_options compression=kLZ4Compression,max_write_buffer_number=8,min_write_buffer_number_to_merge=2,compaction_style=kCompactionStyleLevel,write_buffer_size=268435456,max_background_jobs=4,level0_file_num_compaction_trigger=8,max_bytes_for_level_base=1073741824,max_bytes_for_level_multiplier=8,compaction_readahead_size=2MB,max_total_wal_size=2147483648,writable_file_max_buffer_size=0,recycle_log_file_num=4

1.1.8.2 512GB内存OSD RocksDB参数优化#

对于512GB内存的节点，OSD占用的总内存最好控制在384GB以内。全闪Ceph集群通常都会有CephFS需求，就要预留出最少128GB的内存空间给MDS。

这样24盘每OSD最大占用内存16GB；12盘每OSD最大占用内存32GB。分给OSD底层RocksDB数据库的内存最大8GB。

这样反推出： 8GB = max_write_buffer_number (32) * write_buffer_size (256MB)

# 调整RocksDB配置
ceph config set osd bluestore_rocksdb_options compression=kLZ4Compression,max_write_buffer_number=32,min_write_buffer_number_to_merge=6,compaction_style=kCompactionStyleLevel,write_buffer_size=268435456,max_background_jobs=4,level0_file_num_compaction_trigger=8,max_bytes_for_level_base=1073741824,max_bytes_for_level_multiplier=8,compaction_readahead_size=2MB,max_total_wal_size=8589934592,writable_file_max_buffer_size=0,recycle_log_file_num=4

1.1.8.3 OSD内存参数优化#

基于上面的计算公式找到合适的OSD内存建议值

# 设定OSD内存最大6GB

1.1.10 创建 crush rule#

## 创建副本 crush rule
## ceph osd crush rule create-replicated <name> <root> <failure-domain> <class>
ceph osd crush rule create-replicated rep_hdd default host hdd
ceph osd crush rule create-replicated rep_ssd default host ssd

## 创建纠删码 crush rule
## ceph osd crush rule create-replicated <name> <root> <failure-domain> <class>
## ceph version >= 20.2, 开启 Fast EC 且设置 stripe_unit=16384 提升性能
ceph config set global osd_pool_default_flag_ec_optimizations true
ceph config set global osd_pool_erasure_code_stripe_unit 16384
## 创建 EC 8+2 纠删码，存储集群推荐 11 个节点起步
ceph osd erasure-code-profile set ec82_ssd k=8 m=2 crush-root=default crush-failure-domain=host crush-device-class=ssd
ceph osd erasure-code-profile set ec82_hdd k=8 m=2 crush-root=default crush-failure-domain=host crush-device-class=hdd
## 创建 EC 6+2 纠删码，存储集群推荐 9 个节点起步
ceph osd erasure-code-profile set ec62_ssd k=6 m=2 crush-root=default crush-failure-domain=host crush-device-class=ssd
ceph osd erasure-code-profile set ec62_hdd k=6 m=2 crush-root=default crush-failure-domain=host crush-device-class=hdd
## 创建 EC 4+2 纠删码，存储集群推荐 7 个节点起步
ceph osd erasure-code-profile set ec42_ssd k=4 m=2 crush-root=default crush-failure-domain=host crush-device-class=ssd
ceph osd erasure-code-profile set ec42_hdd k=4 m=2 crush-root=default crush-failure-domain=host crush-device-class=hdd
## 创建 EC 2+2 纠删码，存储集群推荐 5 个节点起步
ceph osd erasure-code-profile set ec22_ssd k=2 m=2 crush-root=default crush-failure-domain=host crush-device-class=ssd
ceph osd erasure-code-profile set ec22_hdd k=2 m=2 crush-root=default crush-failure-domain=host crush-device-class=hdd
> * 缺省自带副本类 crush rule `replicated_rule`，如果系统中存在 HDD 和 SSD 两类设备这将混用在一起，这会带来不稳定性能。
> * 一般显示创建副本类 crush rule 指定设备类型（例如上面明确 ssd 设备）

每个 Pool 中的 PG 数量会影响到性能，Ceph 提供自动调整 PG 数量功能。

二、其它#

* 使用多路径设备，重启节点 lvm 别名设备丢失问题

    这是因为重启节点时 lvm 先处理 /dev/sd* 设备导致被锁定，无法处理对应 /dev/mapper/mpath* 设备
    

# 打开文件
/etc/lvm/lvm.conf
# 添加一行, 让 lvm 只处理 /dev/mapper/mpath* 设备
filter = [ "a|/dev/mapper/mpath.*|", "r|.*|" ]

# 然后执行 
update-initramfs -u
# 重启节点
reboot
