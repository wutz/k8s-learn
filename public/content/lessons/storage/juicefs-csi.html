部署 JuiceFS#

JuiceFS 是一个开源的分布式文件系统，支持多种对象存储后端。

使用 JuiceFS 的原因是可以在机械盘构建的对象存储上，再配合客户端缓存盘，实现高性能、低成本的存储解决方案。

JuiceFS 主要包含 3 种版本，分别是：

  • JuiceFS 社区版: 开源版本免费使用，支持客户端缓存盘, 需要自己分别提供元数据和对象存储
  • JuiceFS 云版本: 相比开源版本，在各个云厂商上有部署好的元数据存储提供，需要自己提供对象存储, 相比社区版支持分布式缓存（用于解决单节点缓存空间有限，以及缓存在其它计算节点上问题）
  • JuiceFS 企业版: 可以部署在私有集群上，元数据服务由原厂提供, 对象存储需要自己提供, 相比社区版本支持分布式缓存

以下所有部署方式均是基于 JuiceFS 社区版本：

  • 云上：元数据可以选择云厂商提供的 RDS 版本的 Redis，对象存储直接使用云厂商提供的版本即可
  • 云下：
    • 元数据
      • 对于开发用途的使用单机实例 Redis，或者对数据一致性要求没有那么高使用 HA Redis
      • 对于数据一致性要求很高，元数据数量超过 2 亿以上使用 TiKV
    • 对象存储
      • 社区上有小规模使用 MinIO, 规模稍大使用 SeaweedFS 案例
      • 在大规模成熟方案还有 Ceph, Ceph 提供 2 种方式
        • Ceph RGW 支持 S3 接口
        • Ceph RADOS 提供原生 Ceph 接口，相比 Ceph RGW 减少中间协议转发层开销以及负载均衡开销

以下部署方式使用方案：

  • 元数据 (选择一个）：
    • Redis 适合文件数量在 1 亿以下，数据一致性要求不高场景
      • 单机版本 Redis 适合开发测试
    • PostgreSQL 适合文件数量在 10 亿
    • TiKV 适合文件数量在 100 亿，数据一致性要求高场景生产环境
      • 部署 TiKV 集群
  • 对象存储
    • Ceph RADOS
    • Ceph RGW
    • RustFS 作为 minio 平替用于开发测试

部署 JuiceFS CSI#

helmwave up --build

部署 JuiceFS#

可以在一个集群中部署多个 JuiceFS，下面分别演示元数据是 Redis 和 TiKV 的场景:

  • JuiceFS 使用 PostgreSQL 作为元数据用于开发场景
    • 复制示例 cp -a examples/postgresql-s3/shared-juice .
    • 修改元数据连接信息: 修改文件 shared-juice/secret.yaml 中的 metaurl 为实际值
    • 修改对象存储连接信息
  • JuiceFS 使用 Redis 作为元数据用于开发场景
    • 复制示例 cp -a examples/redis-minio/shared-juice .
    • 修改元数据连接信息: 修改文件 shared-juice/secret.yaml 中的 metaurl 为实际值
    • 修改对象存储连接信息
  • JuiceFS 使用 TiKV 作为元数据用于生产场景
    • 复制示例 cp -a examples/tikv-ceph/shared-juice .
    • 修改元数据连接信息: 修改文件 shared-juice/secret.yaml 中的 metaurl 为实际值
    • 修改对象存储连接信息
    • 放置 ceph 配置文件到 shared-juice/ceph 中
    • 如果提供的 ceph 配置不是 ceph.client.jfs02.keyring 则需要修改 kustomization.yaml 中的实际文件名称，以及 shared-juice/secret.yaml 中的 secret-key 为实际值
    • 最后修改 shared-juice/secret.yaml 中的 bucket 值，其值为 ceph pool 名称
    • 使用 TiKV 场景 JuiceFS CSI 存在问题, 请按照问题 workaround 进行操作
# 部署执行
kubectl apply -k shared-juice/

# 验证
kubectl apply -f tests.yaml

卸载#

# 卸载 JuiceFS
kubectl delete -k shared-juice/

# 卸载 JuiceFS CSI
helmwave down
