Rook Ceph#

基本概念#

Ceph 基本概念与架构

准备#

  • 至少 3 台机器，每台至少插入 1 块本地盘
  • 推荐额外配置 1 条网络用于集群内数据复制, 可以极大提升存储性能
    • 如果只有 1 条网络，则移除 rook-ceph-cluster 配置中的 cephClusterSpec.network
    • 如果有 2 条网络，根据实际的宿主机网络设置 public 和 cluster 网段
  • 为存储节点打上额外 label, 即只有这些节点会部署 rook 集群
kubectl label node sn-10-254-41-1 node-role.kubernetes.io/storage=true
kubectl label node sn-10-254-41-2 node-role.kubernetes.io/storage=true
kubectl label node sn-10-254-41-3 node-role.kubernetes.io/storage=true
kubectl label node sn-10-254-41-4 node-role.kubernetes.io/storage=true

部署 Operator#

kubectl apply -k operator/

# 等待 operator 就绪
kubectl wait -n rook-ceph --for=condition=ready pod -l app=rook-ceph-operator

部署 CephCluster#

根据实际情况修改 cluster/patch.yaml 中的 public 和 cluster 网段

# 部署 CephCluster
kubectl apply -k cluster/

# 查看 CephCluster 状态
kubectl get cephclusters

# 查看 CephCluster 详细信息
kubectl describe cephcluster rook-ceph

安装 kubectl-rook-ceph 用于运维#

  1. 安装 krew
  2. 安装 kubectl-rook-ceph 执行 kubectl krew install rook-ceph
  3. 使用 kubectl rook-ceph ceph -s 命令查看集群状态

也可以部署 toolbox kubectl apply -k toolbox/ 然后登录 kubectl exec -it rook-ceph-tools-xxx-xxx bash 执行 ceph 管理工具

排错#

  • 查看 osd 数量是否符合预期
# 查看 osd 数量是否符合预期
kubectl rook-ceph ceph osd tree
kubectl get po -n rook-ceph

# 查看 osd 准备日志，找到未加入 osd 原因
kubectl -n rook-ceph get pod -l app=rook-ceph-osd-prepare
kubectl -n rook-ceph logs rook-ceph-osd-prepare-xxx-xxx provision

# 重启 operator 触发重新发现 osd
kubectl rollout restart deployment rook-ceph-operator
或者执行
kubectl rook-ceph operator restart

通常 osd 未加入是磁盘或者之前集群残留，参见 销毁集群 章节

配置 CephCluster#

## ceph version >= 20.2, 开启 Fast EC 且设置 stripe_unit=16384 提升性能
kubectl rook-ceph ceph config set global osd_pool_default_flag_ec_optimizations true
kubectl rook-ceph ceph config set global osd_pool_erasure_code_stripe_unit 16384
## 查看配置是否生效
kubectl rook-ceph ceph config dump

创建 RBD 块存储#

  • 创建 rbd 存储池和 storageclass

    • 每个租户需要使用独立的 rbd 部署
    • 复制示例 rbd/block-ceph.yaml, 修改所有 block-ceph 为实际的名称
    • 根据实际情况修改 CephBlockPool.spec.deviceClass 为 hdd 或 ssd 等
kubectl apply -f rbd/block-ceph.yaml

  • 测试验证 RBD 工作正常

    测试验证 RBD 工作正常, 首先修改 rbd/tests/pvc.yaml 中的 storageClassName 为实际的名称

kubectl apply -k rbd/tests/

kubectl exec -it csirbd-demo-pod -- bash

创建 CephFS 文件系统#

  • 创建 cephfs 文件系统和 storageclass

    • 每个租户需要使用独立的 cephfs 部署
    • 复制示例 cephfs/shared-ceph.yaml, 修改所有 shared-ceph 为实际的名称
    • metadataPool
      • deviceClass 必须配置为 ssd
      • replicated.size 独立存储集群配置为 3, 融合存储集群配置为 4
    • dataPools
      • name: replicated
        • replicated.size 独立存储集群配置为 3, 融合存储集群配置为 4
      • name: erasurecoded
        • deviceClass 根据实际情况选择 hdd 或 ssd
        • erasurecoded.dataChunks 配置为 4
        • erasurecoded.codingChunks 独立存储集群配置为 2, 融合存储集群配置为 3
    • 生产环境 metadataServer.resources.memory 至少 32Gi, 其与热元数据数量相关, 每个元数据大约占用内存 3k 大小，如果元数据缓存大小不足则会频繁回收内存造成严重性能下降
    • 缺省使用纠删码其得盘率更高，如果需要更高性能则可以使用副本，注释 dataPools.erasurecoded 整段配置, 并修改 StorageClass.parameters.pool 为 shared-ceph-replicated
kubectl apply -f cephfs/shared-ceph.yaml

  • 测试验证 CephFS 工作正常

    测试验证 CephFS 工作正常, 首先修改 cephfs/tests/pvc.yaml 中的 storageClassName 为实际的名称

kubectl apply -k cephfs/tests/

kubectl exec -it csicephfs-demo-pod -- bash

重要配置#

  • pg-autoscaler 不工作问题，这会造成性能不能充分利用
# 查看到所有 Pool 的 PGS 数量为 1
kubectl rook-ceph ceph osd df 

# 除第一个 replicated_rule 外，获取第二个值例如 block-ceph
kubectl rook-ceph ceph osd crush rule ls

# 设置 Pool .mgr 的 Crush Rule
kubectl rook-ceph ceph osd pool set .mgr crush_rule block-ceph

# 查看 Pool 的 Autoscale 状态, 每个 Pool 的 PGS 至少为 32
rook-ceph ceph osd pool autoscale-status
  • 设置数据均衡优先
kubectl rook-ceph ceph config set osd osd_mclock_override_recovery_settings true
kubectl rook-ceph ceph config set osd osd_max_backfills 16
kubectl rook-ceph ceph config dump

使用 Ceph Dashboard#

通常不直接使用 Ceph Dashboard 管理集群而是使用 rook, Ceph Dashboard 作为一个 GUI 查看工具

kubectl port-forward svc/rook-ceph-mgr-dashboard 8443

访问 https://localhost:8443 即可, 用户名为 admin, 密码使用下面命令获取

kubectl -n rook-ceph get secret rook-ceph-dashboard-password -o jsonpath="{['data']['password']}" | base64 --decode && echo

销毁集群#

# 销毁集群
kubectl rook-ceph destroy-cluster
# 输入 yes-really-destroy-cluster 后开始执行

# 删除 operator
kubectl delete -k operator/

# 删除宿主机残留
pdsh -w sn-10-254-41-[1-4] 'rm -rf /var/lib/rook'

# 抹除磁盘,下面方法任选其一
pdsh -w sn-10-254-41-[1-4] 'sgdisk --zap-all /dev/xxx'
pdsh -w sn-10-254-41-[1-4] 'dd if=/dev/zero bs=1M count=100 oflag=direct,dsync of=/dev/xxx'
# ssd 使用 blkdiscard 抹除而非 dd
pdsh -w sn-10-254-41-[1-4] 'blkdiscard /dev/xxx'

# 如果仍然无法抹除，可以使用 ceph-volume
ceph-volume lvm zap /dev/xxx
