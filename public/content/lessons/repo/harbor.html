Harbor 镜像仓库（Istio Ingress）#

Harbor 是一个用于存储和分发 Docker 镜像的仓库，支持 Docker Registry、Helm Chart 等多种镜像格式。

本方案是仓库服务的备选镜像仓库。缺省方案是 Registry，两者部署其一即可。

相比 Registry，Harbor 额外提供项目级 RBAC (可对接 LDAP / OIDC)、上游镜像代理缓存、漏洞扫描与镜像签名、保留策略和仓库间复制；代价是组件更多、资源开销更高，生产环境还需要外接 PostgreSQL 与 Redis。选型对比见 仓库服务。

本方案使用 Istio ingressgateway 替代 Nginx Ingress Controller 作为 Ingress 控制器，Harbor chart 原生支持 ingressClassName，无需额外自定义资源。

部署#

访问 values.yml 文件，进行修改:

  • expose.type 选择访问模式（二选一）:

    Ingress + TLS LoadBalancer
    适用 域名 + HTTPS 访问 IP 直连，内网简单使用
    expose.type ingress loadBalancer
    tls.enabled true false
    certSource secret -
    hosts.core 域名 (如 cr.mc01.example.com) -
    externalURL https://cr.mc01.example.com http://<LB-IP>
    额外步骤 kubectl apply -k . 无

    externalURL 是 Harbor 的外部入口地址（写入 Core 的 EXT_ENDPOINT），docker login/push/pull 的回调重定向都依赖此值，必须与客户端实际访问地址一致

    • Ingress 模式: https:// + hosts.core 域名
    • LoadBalancer 模式: http:// + MetalLB 分配的 ExternalIP；如果 IP 未提前指定，先部署后获取: kubectl get svc -n harbor harbor -o jsonpath='{.status.loadBalancer.ingress[0].ip}'，然后更新 values.yml 再 helmwave up --build

    Ingress + TLS 模式: certSource: secret，TLS Secret 必须在 istio-system namespace 创建（Istio 要求）

    • 生产环境: 向管理员申请域名和正式 TLS 证书，将证书文件放到 tls/ 目录
    • 测试环境: 执行 ./tls/gen-cert.sh 自动生成自签名证书
    • 部署证书: kubectl apply -k .（IngressClass + EnvoyFilter + TLS Secret）

    域名需同时配置到: values.yml 的 expose.ingress.hosts.core / tls/gen-cert.sh 的 DOMAIN

    LoadBalancer 模式: MetalLB 分配 ExternalIP，流量直达 Harbor 内置 nginx，不经过 Istio，无需配置 IngressClass 和证书

  • expose.ingress.className 设为 istio，对应 istio/ingressclass.yaml 中定义的 IngressClass

  • persistence.persistentVolumeClaim.*.storageClass 配置集群存在的共享存储，以及大小

  • database.type 需要修改为 external 用在生产环境中以及添加 external 对应连接信息；用在开发环境保持不变即可

  • redis 修改等同于 database

  • harborAdminPassword 配置管理员密码

  • proxy: 可选，可以用于 harbor 作为 image proxy 使用

Ingress 模式需先应用 Istio 相关资源（LoadBalancer 模式跳过此步直接 helmwave）:

# HTTPS 场景 — 测试环境: 先生成自签名证书
# 生产环境: 向管理员申请证书，放到 tls/ 目录 (tls.key + tls.crt)
./tls/gen-cert.sh

# 一键部署 (IngressClass + EnvoyFilter + TLS Secret)
# Istio 要求 Ingress 的 TLS Secret 必须在 ingressgateway 的 namespace (istio-system) 中
# 参见: https://istio.io/latest/docs/tasks/traffic-management/ingress/kubernetes-ingress/
kubectl apply -k .
helmwave up --build

已知问题#

  • 使用 image-syncer 同步镜像报错 blob upload valid，在 juicefs/nfs 等非强一致文件系统使用多实例 harbor-registry 会触发此问题
  • 缺省情况下，Harbor 支持的镜像单层 layer 最大为 128GB。values.yml 中已通过 core.extraEnvVars 将 BEEGO_MAX_UPLOAD_SIZE_BYTES 和 BEEGO_MAX_MEMORY_BYTES 调整为 500GiB，如需进一步调整修改对应值即可
  • certSource=auto 创建的 Secret 在 harbor namespace，Istio 找不到，HTTPS 不通；必须使用 certSource=secret，通过 kubectl apply -k . 在 istio-system 创建 Secret
  • EnvoyFilter harbor-upload-tuning 作用于所有 ingressgateway 流量（不仅限 Harbor），多服务共用同一 ingressgateway 时需评估超时参数是否影响其他服务

提供镜像代理服务 (可选)#

  1. 选择仓库管理，然后新建目标, 选择提供者Docker Registry，并填写目标名（例如 docker.io/gcr.io 等),最后填写对应目标URL, 下面是目标名与目标URL的对应关系:
目标名 目标URL
docker.io https://mirror.gcr.io
gcr.io https://gcr.io
ghcr.io https://ghcr.io
k8s.gcr.io https://k8s.gcr.io
registry.k8s.io https://registry.k8s.io
nvcr.io https://nvcr.io
quay.io https://quay.io

使用harbor 命令行配置 Registry （可选）#

  • 下载安装： https://github.com/goharbor/harbor-cli/releases

  • 登陆私有 harbor

harbor login https://cr.mc01.example.com -u admin -p Harbor12345
  • 批量创建 registry
for registry in docker.io gcr.io ghcr.io k8s.gcr.io registry.k8s.io nvcr.io quay.io; do
  url="https://$registry"
  [ "$registry" = "docker.io" ] && url="https://mirror.gcr.io"
  harbor registry create --name "$registry" --type docker-registry --url "$url"
done
